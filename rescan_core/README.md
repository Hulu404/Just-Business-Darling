# rescan_core

Ядро сервиса rescan. Возвращаем пациента к врачу клиники после анализа крови:
принимаем событие «анализы готовы» из МИС, делим на группы 75/25, ставим в
очередь врача, отправляем сообщение, принимаем заявку, ведём маршрут, считаем
отчёт против контрольной группы.

## Что сделано

| Пункт | Что это | Статус |
|---|---|---|
| **B1** | Каркас: PostgreSQL, миграции, 16 таблиц, роли, аудит | ✅ готово |
| **B2** | Приём событий МИС: HMAC, идемпотентность, CSV | ✅ готово |
| B3 | Группы 75/25 | ✅ сделано попутно |
| B4–B12 | Очередь врача, доставка, заявки, отчёт и т.д. | ⏳ следующий этап |

## Быстрый старт (краткая версия)

Подробная инструкция по настройке, БД и проверке — в **`docs/setup.md`**.
Что нужно знать лично тебе (вторая разработчица) — в **`docs/for-you.md`**.

```bash
python -m venv .venv
# Windows: .venv\Scripts\activate ; macOS/Linux: source .venv/bin/activate
pip install -e ".[dev]"
cp .env.example .env          # отредактируй DATABASE_URL под свою БД
python -m scripts.seed_demo   # создаёт таблицы и пишет демо-клинику
uvicorn app.main:app --reload # http://127.0.0.1:8000/docs
pytest                        # тесты
```

## Структура репозитория

```
rescan_core/
├── app/
│   ├── main.py                     # сборка FastAPI, /health
│   ├── config.py                   # настройки из env
│   ├── api/v1/mis.py               # POST /v1/mis/results-ready, /visits-csv
│   ├── schemas/events.py           # контракт события и CSV
│   ├── security/
│   │   ├── hmac.py                 # подпись вебхуков МИС (B2)
│   │   ├── crypto.py               # шифрование контактов (B11)
│   │   └── roles.py                # роли врач/админ/руководитель (B1)
│   ├── services/
│   │   ├── ingest_service.py       # приём события целиком (B1+B2)
│   │   ├── group_service.py        # группы 75/25 (B3)
│   │   ├── csv_parser.py           # разбор CSV с видимыми ошибками
│   │   └── audit.py                # журнал без ПДн (B1)
│   ├── repositories/               # доступ к данным (SQLAlchemy)
│   └── db/                         # engine, сессии, 16 моделей
├── migrations/                     # Alembic: env.py + начальная миграция
├── scripts/seed_demo.py            # создать таблицы + демо-данные
├── tests/                          # pytest
├── docs/                           # setup.md, for-you.md, contract.md
├── .vscode/                        # настройки и отладка VS Code
├── pyproject.toml
└── alembic.ini
```

CI расположен в корне репозитория: `.github/workflows/rescan-core.yml`.
Он проверяет lint, типы, миграции и тесты на SQLite и PostgreSQL.

После обновления от 17.10.2026 выполните `python -m alembic upgrade head`:
миграция очищает сохранённые исходные тела событий и расширяет ID аудита.
Очистка тел необратима; старые резервные копии не изменяются.
Отправители МИС должны включать timestamp в подпись — см. `docs/contract.md`.

## Правила проекта (не нарушать)

- Персональные данные (телефон) — только в таблице `contacts`, только
  зашифрованные. Поля о здоровье (результаты, диагнозы) в системе отсутствуют.
- Телефон не попадает в логи и в аудит.
- Контракт в `app/schemas/events.py` меняется только по согласованию с командой
  (от него зависят фронтенд и отчёт).
- Группа пациента фиксируется один раз при первом событии и не пересчитывается.
