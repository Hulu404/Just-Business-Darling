# 10. По желанию: приём готового ИИ-заключения

## Зачем

Кейс сформулирован так: сервис получает ИИ-заключение по исследованию и определяет следующий шаг пациента. Сейчас вход один — собственный сервис снимков, которому нужен архив DICOM. Клиника, у которой ИИ-сервис уже описывает исследования, заключение имеет, а передать его нам не может. Нужен второй вход: готовое заключение внешнего ИИ.

Правило безопасности остаётся прежним: в маршрут попадает только заключение, подтверждённое врачом. Внешний ИИ даёт черновик, врач его подтверждает, и только тогда шлюз отправляет заключение в сервис пути.

Задание меняет приём заключений в сервисе пути. Согласуй это с автором сервиса до начала.

## Что сделать

### 1. Сервис пути: больше одного источника заключений

Сейчас `validate_report` принимает только `source_service: "medmarshrut_image_service"`, а подпись проверяется одним секретом.

- Новая переменная `PATH_SOURCE_SECRETS`: JSON-объект «`source_service` → секрет не короче 16 символов». `PATH_SHARED_SECRET` остаётся секретом сервиса снимков, поэтому существующий запуск и тесты не меняются.
- Подпись проверяется секретом того источника, который назван в заключении. Источника нет в настройках — 403. Заключение источника А, подписанное секретом источника Б, — 403.
- `confirmation_status: "confirmed"` обязателен для любого источника.
- Ключ идемпотентности уже включает `source_service`: проверь тестом, что одинаковые `source_report_id` у разных источников не конфликтуют.
- Тесты: сервис снимков работает как раньше; второй источник принимается со своим секретом; три случая отказа выше.
- README сервиса и `docs/api-contracts.md`.

### 2. Шлюз: вход для внешней системы

`POST /api/integrations/ai-reports` — без сессии, с подписью по тем же правилам (`X-Path-Timestamp`, `X-Path-Signature`), секрет `GATEWAY_AI_SOURCE_SECRET`. Тело:

```json
{"source_system": "third-opinion-demo", "external_id": "abc-123", "model": "chest-xray-1.4",
 "study_type": "xray", "study_uid": "1.2.3.4", "anatomy": "CHEST", "protocol_name": "CHEST_PA",
 "patient_ref": "demo-patient-1", "finding_class": "infiltrate",
 "ai_conclusion": "Текст черновика", "confidence": 0.91, "created_at": "2026-10-04T10:00:00+03:00"}
```

- Черновик сохраняется в базе шлюза со статусом «ждёт врача». Пара `source_system` и `external_id` идемпотентна: точный повтор возвращает ту же запись, другое содержимое под тем же ключом — 409.
- Проверки: длины строк, время с поясом, `confidence` от 0 до 1 или `null`, `patient_ref` по шаблону сервисов. Текст черновика — недоверенный ввод: только через экранирование.
- До подтверждения черновик видит только врач. Координатор и пациент не видят ничего.
- Соответствие классов внешней системы кодам клиники лежит в `demo_stand/ai_code_map.demo.json`: `source_system` → `finding_class` → `finding_code`. Незнакомый класс не угадывается: он уходит в сервис пути как есть и попадает на ручной разбор с причиной `unknown_finding_code`.

### 3. Подтверждение врачом

- В рабочем списке врача («Что на снимке») появляется блок «Заключения внешнего ИИ» с названием системы и модели.
- Экран черновика — тот же «Снимок и заключение», но без просмотра срезов: на его месте сведения об исследовании и строка «Снимки хранятся в РИС клиники». Врач читает и правит текст, подтверждает или отклоняет с причиной.
- При подтверждении шлюз отправляет в сервис пути подписанное заключение (тело до 16 КиБ, сериализация с `ensure_ascii=False`): `source_service: "medmarshrut_gateway_service"`, `source_report_id` из `source_system` и `external_id`, `source_model` из названия системы и модели, `physician_id` из сессии врача, `confirmed_at` — момент подтверждения, `confidence` — как прислала система. Секрет — из `PATH_SOURCE_SECRETS`.
- Отклонённый черновик в сервис пути не уходит. Он остаётся в журнале шлюза.
- В карточке обращения источник черновика показан так же, как в прототипе: «Черновик: ИИ-сервис …» и «Подтвердил: …».

### 4. Имитация внешней системы на стенде

- `demo_stand/send_ai_report.py` — отправляет в шлюз подписанное синтетическое заключение для выбранного пациента. Если часть А задания 09 выполнена — рентген грудной клетки с классом, который соответствует `DEMO_XR_INFILTRATE`; если нет — КТ.
- `start.py` выдаёт шлюзу и скрипту `GATEWAY_AI_SOURCE_SECRET`, сервису пути и шлюзу — секрет источника `medmarshrut_gateway_service`.
- На «Карте сервисов» в блоке «Откуда приходят данные» у узла ИИ-сервиса — кнопка «Прислать заключение (демо)». Браузер секрета не знает: кнопка вызывает обычный маршрут с сессией, например `POST /api/demo/ai-report`, а шлюз сам составляет заключение и кладёт его в тот же приём, что и подписанный вход. Везде, где упоминается внешний ИИ-сервис, стоит пометка «демо-интеграция»: настоящего обмена с чужой системой на стенде нет.
- `seed.py`: один черновик внешнего ИИ ждёт врача.
- `smoke.py`: заключение приходит → врач подтверждает → эпизод с шагом по правилу; второй черновик врач отклоняет → эпизода нет.

## Тесты

- Шлюз: подпись входа, идемпотентность, лимиты; черновик не виден координатору и пациенту; подтверждение доступно только врачу; отклонённый черновик не порождает запросов к сервису пути; незнакомый класс не подменяется.
- Сервис пути: тесты из пункта 1.

## Готово, когда

- Заключение внешней системы проходит путь: пришло → врач подтвердил → шаг по правилу → пациент видит результат и записывается.
- Без подтверждения врача в сервис пути не уходит ничего.
- Старый вход через сервис снимков работает без изменений.
- Все наборы тестов зелёные, `python start.py --smoke` проходит.
