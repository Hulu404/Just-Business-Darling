# Правила цикла для заданий 12–15

Задания 12–15 выполняются циклами. Один запуск промта — один цикл: один пункт из раздела «Циклы» в файле задания. Между запусками разговор может быть сжат, поэтому состояние живёт в файлах и в git, а не в памяти разговора.

## Где лежит состояние

- **Файл задания** — `prompts/NN-….md`. Его не меняй.
- **Отчёт задания** — `docs/reports/NN-….md`. Начинается с раздела «Ход работ»: список циклов с отметками. Это память цикла.
- **git** — один коммит на цикл в ветке `feature/web-product`.

Отметки в «Ходе работ»: `[ ]` не начат, `[~]` в работе, `[x]` закрыт.

## Что делать в каждом запуске

1. Прочитай `CLAUDE.md`, файл задания и «Ход работ». Если полный текст `CLAUDE.md`, задания и этих правил уже есть в разговоре выше, не перечитывай их: хватит «Хода работ». Не уверен — перечитай. Код читай по частям: только то, что нужно циклу. Отчёта ещё нет — это первый запуск: создай его с «Ходом работ» (все циклы задания, у первого отметка `[~]`) и выполни цикл 0, в задании 14 — А0.
2. Если в «Ходе работ» есть строка `СТОП` без строки `СНЯТО` под ней — ничего не делай: повтори причину и останови цикл.
3. Посмотри `git status` и `git log --oneline -5`. Незакоммиченные правки в файлах, которые нужны циклу, при отметке `[~]` — твой оборванный цикл: продолжи его. Такие же правки без `[~]` — чужая работа: СТОП. Чужие правки в остальных файлах (презентация, заметки, `PROGRESS_*.md`, папка `.claude/`) не трогай и в коммит не бери. Новые файлы заданий в `prompts/` добавь в коммит цикла 0.
4. Возьми первый цикл без `[x]`, поставь ему `[~]`. Делай только его. В следующие циклы не забегай.
5. Выполни проверку цикла. Красная — чини в этом же запуске.
6. Запиши в «Ход работ»: `[x]`, дату и время, что сделано в одной-трёх строках, что проверено и с какими числами, отступления от задания.
7. Сделай коммит: код, тесты, отчёт. Файлы добавляй поимённо, без `git add -A` и `git add .`: в папке есть чужие правки. Сообщение по-русски и коротко, с номером: `rescan 12, цикл 3: предпросмотр шага для врача`.
8. Ответь одной строкой: какой цикл закрыт и какой следующий. Остались циклы — работа продолжается следующим запуском; в `/loop` назначь его через минуту. Закрыт «Финал» — останови цикл и напиши итог.

Не успел закончить цикл за запуск — оставь `[~]`, допиши под ним одну строку «осталось: …» и не коммить. Следующий запуск продолжит.

## Проверки

Быстрая, в каждом цикле:

```
python -B -m unittest discover -s ./medmarshrut_image_service -p "test_*.py" -v
python -B -m unittest discover -s ./medmarshrut_path_service -p "test_*.py" -v
python -B -m unittest discover -s ./medmarshrut_clinic_service -p "test_*.py" -v
python -B -m unittest discover -s ./medmarshrut_medications_service -p "test_*.py" -v
python -B -m unittest discover -s ./medmarshrut_gateway_service -p "test_*.py" -v
```

В браузере, в циклах с экранами:

```
python start.py --web-check
```

Полная, в циклах переключения и в «Финале»: быстрая, затем

```
python start.py --smoke
python start.py --web-check
```

- Признак успеха: `OK` у каждого набора, «Смоук-проверка пройдена: N шагов из N», «Проверка в браузере: N из N». Числа запиши в «Ход работ».
- Стенд для проверок поднимают сами `--smoke` и `--web-check`. Не оставляй `python start.py` работать в фоне: порты 8763–8767 будут заняты, и проверки не запустятся.
- Смоук и проверка в браузере ходят в PostgreSQL из `.env` и требуют Playwright.
- Тесты PostgreSQL идут только с `GATEWAY_TEST_DATABASE_URL`. Без неё они пропускаются: запиши это, а не «пройдено».

Нельзя: ослаблять проверки, удалять или пропускать тесты, поднимать допуски, выключать проверку консоли и CSP, заменять запуск словами «проверено вручную».

Можно и нужно: переводить проверки на новые экраны и добавлять новые. Проверка экрана, который задание убирает, уходит вместе с ним: запиши это в «Ход работ».

## Что уже проверяют тесты

Эти требования зашиты в проверки репозитория. Нарушил — чини код, а не проверку.

- `test_gateway.py` читает каждый файл в `web/`. В `.html`, `.css`, `.js` и `.svg` нельзя: `localStorage` и `sessionStorage`; обработчики в разметке вида `onclick="…"`; адреса с `http://`, `https://` и `//домен`, в том числе `xmlns` у SVG. В `index.html` нет встроенных `<script>`.
- `web_check.py` считает провалом ошибку или предупреждение в консоли, нарушение CSP и горизонтальную прокрутку страницы при 390, 820, 1280 и 1680 на любом экране из `SCREENS`.
- Ответ шлюза с кодом 4xx или 5xx браузер сам пишет в консоль как ошибку. Не запрашивай то, чего может не быть: «данных нет» — это 200 и пустой список. В сценарии, который вызывает отказ нарочно (занятое время, 409), пропусти в консоли ровно эту строку, остальные считай.
- `wait_ready` ждёт, пока в `#view` появится содержимое и исчезнет `.card.skeleton`. Заглушки загрузки новых экранов должны попадать под это ожидание: дай им тот же класс или добавь их признак в `wait_ready`.
- Роль окна проверки читают и переключают через список `#role`. Он в документе один и при ширине 1280 виден.

## Когда останавливаться

Запиши в «Ход работ» строку `СТОП: причина и что нужно от человека`, закоммить отчёт, останови цикл и повтори причину в ответе, если:

- задание расходится с кодом в том, что нужно вызвать или изменить;
- проверка цикла не стала зелёной после трёх разных попыток. Попытки считай в «Ходе работ»: «попытка 2 из 3: что пробовал»;
- нужна правка чужого сервиса, которую задание не разрешает;
- в нужных файлах чужие незакоммиченные правки;
- проверку нельзя запустить: нет сети, базы, браузера или заняты порты;
- до начала работ исходные проверки уже красные;
- нужно решение, которого нет в «Решениях владельца».

Владелец снимает остановку сам: дописывает под строкой `СТОП` строку `СНЯТО: решение` и запускает цикл снова.

## Чего не делать

- Не пушь, не мержи, не переключай ветку, не переписывай историю: без `git reset --hard`, `git rebase`, `git commit --amend` для чужих коммитов.
- Не выводи и не коммить `.env`. Не запускай `python start.py --print-secrets`.
- Не запускай другие задания из `prompts/` и не делай работу следующего задания.
- Не правь чужие сервисы сверх разрешённого в задании. Каждая такая правка — отдельная строка в отчёте.
- Не меняй файл задания и эти правила.

Читай и ищи по этому файлу. Нет файла — запусти скрипт. Нет и образца — СТОП: по решению 2 задания 12 он лежит только на машине владельца, а не в git.
