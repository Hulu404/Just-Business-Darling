# 02. Шлюз: браузер ходит только в него

## Зачем

Сервисы слушают `127.0.0.1`, не отдают CORS-заголовки и защищены bearer-токенами и HMAC-секретами. Браузеру такие секреты доверять нельзя. Нужен шлюз: он раздаёт веб-приложение, держит сессию с ролью и сам ходит в три сервиса. В этом задании строим основу без экранов и без данных: сессии, защиту, клиенты сервисов, проверку состояния. Экраны появятся в 03, данные сервисов — в 04–06.

## Сначала прочитай

- `CLAUDE.md` и `docs/api-contracts.md`, особенно разделы «Общее» и «Подпись между сервисами».
- `docs/reports/01-stand.md`, `start.py`, `demo_stand/people.demo.json`.
- `medmarshrut_path_service/service.py` и `auth.py`: шлюз пишется в том же стиле.

## Что сделать

### Папка `medmarshrut_gateway_service/`

Устройство как у остальных сервисов: stdlib, `ThreadingHTTPServer`, плоские импорты, запуск `python ./medmarshrut_gateway_service/service.py`, адрес `127.0.0.1:8763`.

- `service.py` — обработчик запросов. Маршруты этого задания: `GET /`, `GET /assets/...`, `GET /api/health`, `GET`, `POST` и `DELETE /api/session`.
- `upstream.py` — клиенты трёх сервисов на `urllib`: bearer-токены, подпись, тайм-ауты, разбор ошибок. Функция подписи — копия `signature` из `medmarshrut_path_service/auth.py`.
- `sessions.py` — сессии и роли.
- `store.py` — SQLite шлюза в папке состояния. Таблиц пока нет: они появятся в 04–07. Схема создаётся через `CREATE TABLE IF NOT EXISTS`, как в сервисах.
- `web/index.html` и `web/js/boot.js` — временная страница: название продукта, выбор роли, таблица состояния сервисов. Задание 03 её заменит.
- `test_gateway.py`, `README.md`, `requirements.txt` с одной строкой `# Standard library only.`

### Окружение

Имена совпадают с именами сервисов, чтобы `start.py` раздавал один набор.

| Переменная | Что это |
|---|---|
| `REVIEWER_TOKEN` | токен врача для сервиса снимков |
| `PATH_ADMIN_TOKEN` | токен сотрудника для сервиса пути |
| `PATH_MIS_TOKEN` | необязательный: токен МИС для итогов визита |
| `CLINIC_SHARED_SECRET` | секрет подписи для сервиса клиники |
| `CLINIC_STAFF_TOKENS` | тот же JSON «токен → `clinic_id`», что у сервиса клиники; шлюз переворачивает его в «`clinic_id` → токен» |
| `GATEWAY_HOME_CLINIC` | своя клиника, по умолчанию `clinic-central` |
| `GATEWAY_STATE_DIR` | папка состояния стенда |
| `GATEWAY_PEOPLE` | путь к `people.demo.json` |
| `GATEWAY_IMAGING_MODE` | `demo-scripted`, `model` или `no-model`: что запущено в роли сервиса снимков, нужно для подписи в интерфейсе |
| `IMAGE_URL`, `PATH_URL`, `CLINIC_URL` | необязательные адреса сервисов, по умолчанию порты 8766, 8765, 8764. Нужны тестам. Принимается только хост `127.0.0.1` |
| `GATEWAY_PORT` | необязательный порт шлюза, по умолчанию 8763. Нужен тестам, чтобы не мешать запущенному стенду |

Шлюз не стартует, если обязательный секрет не задан или короче 16 символов, и говорит, какого именно не хватает. Сервисы пути и клиники ведут себя так же.

### Сессии: по одной на роль

На защите роли открыты в соседних окнах одного браузера. Одна общая кука сломала бы показ: выбор роли в одном окне менял бы её в другом. Поэтому у каждой роли своя сессия и своя кука.

- Роли: `patient`, `staff`, `doctor`, `partner`.
- Каждый запрос к `/api/` несёт заголовок `X-MM-Role` с ролью окна. Шлюз берёт сессию из куки этой роли: `mm_session_patient`, `mm_session_staff` и так далее (`HttpOnly; SameSite=Strict; Path=/`). Окна разных ролей работают одновременно и друг другу не мешают.
- `POST /api/session` с телом `{"role": "..."}` создаёт сессию этой роли. Необязательные поля: `patient_ref` для пациента (по умолчанию `demo-patient-1`; шлюз проверяет его подписанным `GET /v1/patients/by-ref/{patient_ref}`: домашняя клиника — своя, статус `active`) и `clinic_id` для партнёра (по умолчанию `clinic-partner-1`; клиника должна быть в `CLINIC_STAFF_TOKENS`). Ответ: `{"role", "name", "clinic_id", "patient_ref"}` — те поля, которые есть у роли.
- `GET /api/session` возвращает сессию роли из заголовка или 401. `DELETE /api/session` завершает её.
- Кто стоит за ролью, записано в `people.demo.json`.
- Пароля нет: это локальный демо-стенд. Так и напиши в README шлюза, а `/api/health` пусть отдаёт `"auth": "demo-roles"`. Для пилота нужна настоящая аутентификация.
- Сессии живут в памяти процесса.

### Доступ

- Порядок проверок: неизвестный путь — 404; нет заголовка роли или сессии этой роли — 401; маршрут есть, но его нет в таблице доступа или роль не подходит — 403.
- Таблица «маршрут → роли». По умолчанию запрещено: обработчик без строки в таблице не работает.
- `actor`, `physician_id`, `author_id`, `clinic_id` и `created_by` в запросах к сервисам берутся из сессии. Из тела запроса браузера их брать нельзя. `patient_ref` у пациента тоже берётся из сессии; сотрудник и врач называют пациента явно.
- Заготовь общую проверку «объект принадлежит пациенту этой сессии». Она понадобится в 04 и 05.

### Защита

1. Слушает только `127.0.0.1`. Заголовок `Host` сверяется со списком (`127.0.0.1:<порт>`, `localhost:<порт>`), иначе 403: это защита от подмены DNS.
2. Запросы, которые что-то меняют, проходят только с `Origin` шлюза (или без `Origin`), с заголовком `X-MM-Role` и с `Content-Type: application/json`. Исключение по типу тела — загрузка архива в задании 05.
3. Секреты и токены сервисов не попадают в ответы, логи и файлы `web/`.
4. Заголовки на каждый ответ: `X-Content-Type-Options: nosniff`, `Referrer-Policy: no-referrer`; на ответы API — `Cache-Control: no-store`.
5. HTML отдаётся с `Content-Security-Policy: default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data: blob:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none'`. Скрипты — только из файлов: встроенных скриптов и обработчиков в атрибутах в продукте не будет. Встроенные стили разрешены, потому что в прототипе 114 атрибутов `style`.
6. Статика отдаётся только из `web/`, по списку расширений (`.html`, `.css`, `.js`, `.svg`, `.png`, `.ico`), без выхода за пределы папки.
7. Тело JSON — до 32 КиБ. Размер проверяется по `Content-Length` до чтения тела.
8. Трассировки в ответы не уходят.

### Клиенты сервисов

Сервисы строги к формату и местами хрупки (раздел «Общее» в `docs/api-contracts.md`). Клиент в `upstream.py` это учитывает:

- JSON сериализуется с `ensure_ascii=False`, подпись считается по тем же байтам, которые уходят в запрос;
- типы и длины значений проверяются до вызова сервиса: неожиданный тип может уронить обработчик сервиса без ответа;
- обрыв соединения и тайм-аут — это ошибка сервиса, а не шлюза: 502 или 504 с названием сервиса;
- тайм-аут по умолчанию 10 секунд (для загрузки снимка в 05 понадобится больше).

### Состояние сервисов

`GET /api/health` доступен без сессии:

```json
{"gateway": "ok", "auth": "demo-roles", "imaging_mode": "demo-scripted",
 "services": {"image": {"status": "up", "port": 8766},
              "path": {"status": "up", "port": 8765},
              "clinic": {"status": "up", "port": 8764, "network_version": "..."}}}
```

Статус берётся из `/health` каждого сервиса. Недоступный сервис — `"down"`, сам шлюз при этом отвечает 200.

### Ошибки

Формат шлюза: `{"error": {"code": "...", "message": "..."}}`. `message` пишется по-русски для человека: что случилось и что делать. Сервис недоступен — 502 `upstream_unavailable` с названием сервиса, тайм-аут — 504. Ошибки 400 и 409 от сервиса шлюз передаёт с понятным текстом; английский оригинал кладёт в `detail` для ролей сотрудника, врача и партнёра. Коды сервисов непоследовательны, поэтому текст выбирается по сообщению сервиса, а не по коду.

### Запуск

Добавь шлюз в `start.py` четвёртым процессом, порт 8763 — в проверку портов. После старта `start.py` печатает адрес `http://127.0.0.1:8763`.

## Тесты

`test_gateway.py` на `unittest`. Вместо настоящих сервисов — маленькие поддельные серверы на свободных портах: они записывают запросы и отвечают заготовками. Настоящие сервисы проверяет `python start.py --smoke`.

- Подпись: поддельный сервис проверяет заголовки тем же алгоритмом. Сверь свою функцию с `signature` из `medmarshrut_path_service/auth.py`: загрузи тот файл через `importlib` под другим именем модуля и сравни результаты. Отдельные случаи — `GET` с подписью по пустому телу и тело с кириллицей.
- Сессии: флаги кук; 401 без сессии; сессии двух ролей живут одновременно и не влияют друг на друга; пациент с псевдонимом, которого нет в сервисе клиники, не создаётся.
- Доступ: порядок 404 → 401 → 403; маршрут вне таблицы — 403.
- `Host` не из списка — 403; чужой `Origin` на `POST` — 403; `POST` без `X-MM-Role` — 401.
- Ни один ответ и ни один файл из `web/` не содержит значений секретов: тест перебирает ответы и файлы.
- Статика: выход за пределы `web/` не работает, типы содержимого верные, заголовок CSP на месте.
- Сервис недоступен или оборвал соединение: 502 с понятным текстом, в `/api/health` у него `"down"`.

## Готово, когда

- `python -B -m unittest discover -s ./medmarshrut_gateway_service -p "test_*.py" -v` зелёный, тесты трёх сервисов тоже.
- `python start.py` поднимает четыре процесса. На `http://127.0.0.1:8763` открывается страница, роль выбирается, все три сервиса в состоянии «работает». Если остановить один сервис вручную, страница показывает «недоступен».
- Два окна одного браузера с разными ролями работают одновременно.
- `python start.py --smoke` по-прежнему проходит.
- Код трёх сервисов не изменён.
