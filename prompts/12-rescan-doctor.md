# 12. Кабинет врача rescan на данных шлюза

Задание выполняется циклами по правилам `prompts/rescan-loop.md`. Один запуск — один цикл из раздела «Циклы». Память цикла — «Ход работ» в `docs/reports/12-rescan-doctor.md`.

## Зачем

Владелец задания решил: кабинет врача в продукте выглядит и устроен как в `prototype/rescan-app-standalone.html`, а не как в прежнем прототипе. Это отменяет в `CLAUDE.md` только пункт про источник дизайна и только для роли «врач». Остальные правила `CLAUDE.md` действуют. Экраны координатора и клиники-партнёра не меняются. Приложение пациента — задание 13, здесь его не трогай.

Образец — картинка, а не спецификация. В нём нет ни одного запроса к серверу: люди, находки, сроки и статусы вшиты в код. Задача — надеть его композицию на то, что продукт уже умеет, и не потерять ничего из работающего.

## Решения владельца

Поправь до запуска, если не согласен.

1. В кабинете врача — логотип и название rescan из образца. Координатор и партнёр остаются в «МедМаршруте».
2. Шрифт Stolzl из образца коммерческий (The Northern Block). В git он не попадает: ни файл шрифта, ни образец, в который шрифт вшит. Кабинет подключает шрифт, только когда файл лежит на машине, а без него работает на запасном системном стеке из `--title` и `--body`. Шрифт отдаёт сам шлюз, внешних адресов нет: правило `CLAUDE.md` «без внешних шрифтов» этим не нарушается. Есть лицензия, которая разрешает хранить шрифт в репозитории, — замени этот пункт на «шрифт и образец добавь в git».
3. «Связь с клиникой» (данные живут в памяти вкладки) из меню врача уходит. «Карта сервисов» остаётся у координатора и партнёра.
4. Прежний кабинет врача работает до цикла переключения. Новый до этого открывается только по адресу. Продукт можно показывать после любого коммита.

## Что считать истиной

Маршруты шлюза — это код: `Gateway.routes`, `Gateway.access` и тесты. Известные расхождения с документами — не повод останавливаться:

- маршруты задания 04 не описаны в README шлюза: `/api/catalog`, `/api/slots`, `/api/patient/episodes…`, `/api/staff/episodes…`, `/api/doctor/visits`, `manual-plan`, `revise-plan`, `outcome`, `/api/staff/rules`, `dry-run`, `/api/staff/metrics`;
- в `docs/api-contracts.md` устарели две фразы: «Эндпоинта для чтения правил нет» (`GET /v1/rules` есть) и «`route-candidates` и `referrals` пока никто не вызывает» (их вызывает шлюз).

СТОП — если расходится то, что ты собираешься вызывать: маршрут из таблицы ниже отсутствует в коде, открыт другой роли или отдаёт другие поля.

## Что нельзя потерять

Эти действия врача в продукте есть, и сквозной сценарий на них держится. В образце для них нет места. Найди его в новой композиции и собери из компонентов образца.

- **Итог приёма**: текст, следующие шаги из каталога, свой шаг (`POST /api/doctor/episodes/{id}/steps/{step}/outcome`) — в «Приёмах». Без него пациент не получит следующий шаг. Флажок «Выписать электронный рецепт · демо» в этой форме ничего не отправляет: не переноси его.
- **План врача и смена плана** (`manual-plan`, `revise-plan`) — в «Исследованиях» после подтверждения и в карточке пациента. Шаги предлагай из `GET /api/catalog`, как сейчас в `path-extra.js`: у шага с названием не из каталога не будет слотов, и пациент не сможет записаться.
- **Карта пациента** из сервиса клиники и запись в анамнез (`POST /api/staff/patients/{ref}/anamnesis`) — в карточке «Пациентов».
- **Состояния исследований**: «Ручное описание», «Техническая проверка», «Недоступно», предупреждение «Заключение подтверждено, но не дошло до сервиса маршрута».
- Плашка «Демо-сценарий: признак задан заранее, снимок не анализировался», скрытая оценка модели, подпись «Просмотр для проверки, не диагностический просмотрщик».
- «Улучшить формулировку»: кнопка видна только при включённом помощнике, вариант попадает в поле только по «Подставить».

## Правила переноса

Действуют во всех циклах с экранами, вместе с разделом «Что уже проверяют тесты» в правилах цикла.

**Каркас.**

- Кабинет рисуется внутри `#view`. Боковая панель и шапка прежнего каркаса для новых экранов скрыты. На `#view` завязаны `render()`, загрузка срезов (`hydrate` в `imaging-ui.js`) и ожидания в `web_check.py`.
- Адрес — `#/doctor/<экран>`. В имени экрана допустимы только латинские буквы, и оно не должно совпадать с прежними: `rsToday`, `rsStudies`, `rsPatients`, `rsVisits`, `rsSettings`.
- Список ролей в верхней полосе — тот же, что сейчас в `#role` (пациент, сотрудник, врач, партнёры из `/api/health`), с тем же `id="role"`: на него опираются проверки. В документе он один: в скрытой боковой панели прежний список не рисуй.
- Действия — через существующие `ACTIONS` и `data-action`. Обработчик `data-k` из образца не переноси.
- Модальное окно прежнего каркаса (`#overlay`) живёт вне `#view`, и стили под `#clinic` до него не дойдут. Формы либо оформи под образец отдельным классом, либо рисуй карточкой в правой колонке.
- Без `localStorage` и `sessionStorage`, без CDN и сборки.

**Стили и ресурсы.**

- Стили кабинета — отдельный файл. В образце они ограничены `#clinic` и префиксом `c-`: сохрани это. Глобальные правила образца (`*`, `html, body`, `button, input`, `:root`) не должны менять экраны координатора и партнёра.
- В CSS и JS — пути `/assets/...`. Шрифт через `data:` шлюз блокирует, встроенные `<script>` — тоже.
- Шрифт подключай из кода, а не правилом `@font-face` в CSS: `new FontFace('Stolzl', 'url(/assets/fonts/Stolzl-Regular.otf)')` — и только когда `/api/health` отдал `brand_font: true` (цикл 1). Запрос файла, которого нет, даст 404 и ошибку в консоли.
- Стрелка у `select` в образце — SVG в `data:`-адресе с `xmlns`. Адреса с `http://` в файлах `web/` запрещены тестом: нарисуй стрелку средствами CSS.
- WebGL-анимацию не переноси: в headless Chromium она пишет предупреждения в консоль, а `web_check.py` считает предупреждение ошибкой.
- `<link rel="preconnect" href="https://fonts.googleapis.com">` не переноси.
- Портреты образца нарисованы для вымышленных людей. Пациентам и врачу стенда — инициалы.

**Обновление без перезагрузки.** Списки перечитываются раз в 15 секунд теми же таймерами, что сейчас (`HEALTH_EVERY` в `main.js`). Экран с открытым исследованием и любая открытая форма по таймеру не перерисовываются: правка врача не должна пропасть. Перерисовка не сбрасывает прокрутку и фокус.

**Тексты и данные.**

- Тексты бери из образца там, где они правдивы на стенде. Имя врача — из сессии, дата — текущая, клиника — «Линия здоровья».
- Не переноси: людей, диагнозы, сроки и статусы из `freshPT` и `CASES`; ссылки на клинические рекомендации (Флейшнер, ACR, Stoller, «КР МЗ РФ») — правила стенда учебные; «Третье Мнение» как источник заключений; адрес `rescan.ru/…`; «синхронизировано», «запишется в МИС», «напоминание отправлено», «остальное rescan ведёт сам».
- Срок и шаг не зависят от `confidence`. Срок берётся из `due_at`. У шага, созданного правилом, `due_at` пустой, а срок написан в описании шага: дату сам не вычисляй.
- Всё имитируемое подписано «демо».
- Любое значение с сервера попадает в разметку через `safe()`. В образце большинство подстановок идёт без экранирования: не копируй их как есть.
- У каждого экрана помимо основного вида есть загрузка, пустой список и ошибка с «Повторить». Недоступный сервис — полоса под шапкой, как сейчас.

### Цикл 1. Шлюз: статика и защита

- `.otf` и `.webp` в `STATIC_TYPES`, `font-src 'self'` в `CSP`.
- `GET /api/health` дополнительно отдаёт `brand_font`: лежит ли на диске файл шрифта. По этому признаку приложение решает, запрашивать ли шрифт.
- Тесты: `.otf` и `.webp` отдаются с верным типом — на временной папке вместо `WEB_DIR`, потому что шрифта в git нет; `/assets/index.txt` по-прежнему 404; в CSP есть `font-src 'self'` и по-прежнему `script-src 'self'`; `brand_font` равен `false` без файла и `true` с файлом.
- Строка в README шлюза.

Проверка: быстрая.

### Цикл 2. Шлюз: предпросмотр шага

- `GET /api/doctor/studies/{id}` для исследования в `awaiting_physician` дополнительно отдаёт `preview` по каждому коду находки: шаги или причину ручного разбора и версию правил (`POST /v1/rules/dry-run` сервиса пути, `study_type` — из `MODALITY_TYPES`), плюс утверждённое объяснение из `finding_texts` или `null`.
- `confidence` в запрос не входит. Сервис пути недоступен — `preview: null`, остальной ответ прежний.
- Тесты: шаг по утверждённому правилу; причина при неутверждённом правиле; `preview: null` при недоступном сервисе пути; в `preview` нет `confidence`; пациент и координатор получают 403.
- Строка в README шлюза.

Проверка: быстрая.

### Цикл 3. Шлюз: место и специалист записи

- `GET /api/doctor/visits` дополнительно отдаёт у визита `appointment`: специалист, место, формат из `appointments` и `slots`. Запись у партнёра в эти таблицы не попадает: тогда `null`.
- Тесты и строка в README шлюза.

Проверка: быстрая.

### Цикл 4. Каркас кабинета
