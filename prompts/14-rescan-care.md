# 14. «Лечение» и аптека на сервисе медикаментов

Задание выполняется циклами по правилам `prompts/rescan-loop.md`. Один запуск — один цикл из раздела «Циклы». Память цикла — «Ход работ» в `docs/reports/14-rescan-care.md`.

## Зачем

Во вкладке «Лечение» образца пациент видит назначения, отмечает приём, выбирает аптеку и бронирует лекарство. После задания 13 вкладка пустая: в шлюзе для неё нет ни одного маршрута.

Зато в репозитории лежит `medmarshrut_medications_service` (порт 8767, десять тестов). Он принимает подтверждённый врачом рецепт, подбирает предложения партнёрских аптек и создаёт заказ. Стенд его не запускает, шлюз о нём не знает, в `docs/api-contracts.md` его нет. Задание подключает этот сервис. Свой демо-модуль аптеки в шлюзе не пиши: он повторит чужой сервис и разойдётся с ним.

Модель сервиса строже образца, и продукт следует сервису:

- заказ возможен только по действующему рецепту врача и не больше выписанного количества;
- замена — только если врач разрешил её в рецепте, и только с тем же действующим веществом, формой и дозировкой;
- оплату и выдачу ведёт аптека; кода брони и доставки в сервисе нет;
- схему приёма (`dosage`) пишет врач. Сервис и интерфейс её не предлагают.

## Решения владельца

Поправь до запуска, если не согласен.

1. Аптека работает на сервисе медикаментов. Его код не меняется.
2. Рецепт на стенде передаёт шлюз от имени врача из сессии. Сервис принимает только два источника, `medmarshrut_path_service` и `medmarshrut_mis`: шлюз называется `medmarshrut_mis`, а в интерфейсе стоит «демо: стенд передаёт рецепт вместо МИС». Отдельный источник для шлюза — предложение автору сервиса в отчёте.
3. Каталог и аптеки — поставляемые `catalog.json` и `pharmacies.json`, как есть, с подписью «демо».
4. Статус заказа меняет аптека. Роли аптеки в продукте нет: на стенде это делает встроенная страница сервиса `http://127.0.0.1:8767/staff`.
5. Этап Б (отметки приёма и свои лекарства): **не делаем**. Чтобы цикл выполнил и его, замени на «делаем».

## Контракт сервиса медикаментов

Сверен с кодом. Расхождение с этим списком — СТОП.

- `POST /v1/prescriptions` — подпись `MED_SHARED_SECRET` в заголовках `X-Path-Timestamp` и `X-Path-Signature` (`sha256=` и HMAC-SHA256 от `<timestamp>.<тело>`). Ровно десять полей: `source_service`, `source_prescription_id`, `source_prescription_version`, `patient_ref`, `physician_id`, `confirmed_at`, `expires_at`, `conclusion`, `study_uid`, `items`. Позиция — ровно восемь полей: `inn`, `trade_name` (или `null`), `form`, `strength`, `dosage`, `duration_days`, `quantity`, `substitution_allowed`. Ответ 201, точный повтор — 200 и `duplicate: true`, та же версия с другим содержимым — 409.
- Токен пациента — `Bearer` и hex HMAC-SHA256 от `patient_ref` с ключом `MED_PATIENT_TOKEN`. Сервис узнаёт его только у пациента, у которого уже есть рецепт. Для пациента без рецептов `GET /v1/offers` отвечает 403: это «назначений нет», а не ошибка доступа.
- С токеном пациента: `GET /v1/offers` (несмотря на имя, отдаёт рецепты), `GET /v1/prescriptions/{id}/offers`, `POST /v1/orders`, `GET /v1/orders`, `GET /v1/orders/{id}`, `POST /v1/orders/{id}/cancel`.
- С токеном администратора: `GET /v1/staff/catalog`, `GET /v1/staff/queue`, `GET /v1/staff/metrics`.
- Статусы заказа: `placed` → `confirmed` → `ready` → `picked_up`; `cancelled`, `failed`. Пока заказ не выдан (`placed`, `confirmed`, `ready`), в нём есть `redirect_url` аптеки. На стенде это учебный адрес: показывай его текстом, а не ссылкой.
- Порт 8767 зашит в коде, `GET /health` есть. README сервиса обрывается на команде запуска.
- В сервисах есть одноимённые модули (`service.py`, `store.py`, `auth.py`): в одном процессе их не импортируй, в тестах чужой сервис запускается подпроцессом.

## Маршруты шлюза

Строка в `routes`, строка в `access`, тест и строка в README шлюза на каждый.

| Маршрут | Роль | Что делает |
|---|---|---|
| `GET /api/doctor/medications` | врач | каталог для формы рецепта: действующее вещество, название, форма, дозировка (`strength`), признак «по рецепту» |
| `POST /api/doctor/episodes/{id}/prescriptions` | врач | тело: `event_id`, срок действия в днях, позиции (лекарство из каталога, `dosage` текстом, `duration_days`, `quantity`, `substitution_allowed`). `patient_ref`, `conclusion` и `study_uid` — из эпизода, `physician_id` — из сессии. Шлюз подписывает и отправляет рецепт. `event_id` становится `source_prescription_id`: повтор не создаёт второй рецепт |
| `GET /api/doctor/patients/{ref}/care` | врач | рецепты и заказы пациента для карточки |
| `GET /api/patient/care` | пациент | свои рецепты и заказы. Ответ сервиса 403 для пациента без рецептов — пустые списки |
| `GET /api/patient/prescriptions/{id}/offers` | пациент | предложения аптек по позициям. Чужой рецепт — 404 |
| `POST /api/patient/prescriptions/{id}/orders` | пациент | `pharmacy_id` и позиции; `patient_ref` — из сессии |
| `POST /api/patient/orders/{id}/cancel` | пациент | отмена своего заказа |

## Экраны

- **Врач.** В «Приёмах» и в карточке пациента — «Выписать рецепт». Лекарство выбирается из каталога, схему приёма, длительность и количество врач вводит сам: значений по умолчанию нет. Флажок «Разрешить замену». Подпись «демо: стенд передаёт рецепт вместо МИС». В карточке пациента — рецепты и статусы заказов.
- **Пациент, «Лечение».** Список назначений из рецептов: название, форма и дозировка, текст врача о приёме, дни курса от `confirmed_at` и `duration_days`, срок действия рецепта. Истёкший рецепт виден, заказать по нему нельзя.
- **Пациент, «Где купить».** Аптеки и цены из предложений, подпись «Аптеки и цены учебные». Замена показывается только там, где сервис её вернул, с пометкой «замена, разрешена врачом». Причины пустого списка: нет в каталоге, нет в наличии, рецепт истёк.
- **Пациент, заказ.** «Заказ оформлен», аптека, сумма, статус из сервиса. «Оплата и выдача — в аптеке · демо». Кода брони, времени «забрать сегодня с 12:00» и доставки нет: их не даёт сервис.
- Отдельных уведомлений врачу о заказах нет: статус заказа врач видит в карточке пациента.
- Адрес страницы аптеки в интерфейс не пиши: адреса в файлах `web/` запрещены тестом. Его печатает `python start.py` при запуске.

Не переноси из образца: Витамин D3, Омега-3 и Будесонид с их дозами; аптеки «Листок», «Сфера», «ФармЛинк»; «назначение передано партнёрам»; «Демо: пришло новое назначение из МИС». Правила каркаса, стилей, обновления и экранирования — как в заданиях 12 и 13.

## Готово, когда

- `python start.py` поднимает пять процессов, `/api/health` показывает четыре сервиса.
- Врач выписывает рецепт, пациент видит назначение, предложения аптек и оформляет заказ. Всё переживает обновление страницы.
- Заказать можно только по действующему рецепту: не сверх выписанного количества и без неразрешённой замены. Свободной покупки без назначения врача в сервисе нет, и в интерфейсе её тоже нет.
- В интерфейсе нет доз, замен и аптек, которых не вернул сервис.
- В «Ходе работ» все циклы выбранных этапов и их «Финал» отмечены `[x]`, строк `СТОП` без `СНЯТО` нет.
