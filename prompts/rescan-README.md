# Задания 12–15: запуск циклами в Claude Code

Четыре задания переносят кабинет врача и приложение пациента из образца rescan в продукт. Каждое разбито на циклы: один запуск промта — один цикл с проверкой и коммитом.

| Файл | Что получится | Циклов |
|---|---|---|
| `12-rescan-doctor.md` | Кабинет врача: «Сегодня», «Исследования», «Пациенты», «Приёмы», «Настройки» | 11 и финал |
| `13-rescan-patient.md` | Приложение пациента в телефоне: путь, заключение, запись, записи, календарь, профиль | 10 и финал |
| `14-rescan-care.md` | «Лечение» на сервисе медикаментов: рецепт, предложения аптек, заказ. Этап Б — отметки приёма | 8 и финал, этап Б — ещё 2 |
| `15-rescan-acceptance.md` | Приёмка: опись действий, сквозные сценарии, безопасность, документы | 8 и финал |
| `rescan-loop.md` | Правила цикла, общие для всех четырёх | — |

Порядок: 12 → 13 → 15. Задание 14 — между 13 и 15, если есть время.

Память цикла — раздел «Ход работ» в начале `docs/reports/NN-….md` и коммиты. Разговор может быть сжат или закрыт: цикл продолжит с первого незакрытого пункта.

## Перед запуском

1. **Остановите стенд**, если он запущен: проверки поднимают свой на тех же портах и очищают его папку состояния.
2. **Откройте терминал с тем окружением Python**, в котором у вас проходят `python start.py --smoke` и `python start.py --web-check`. Цикл 0 начинает с этих проверок и остановится, если они красные.
3. **Ветка `feature/web-product`**, в коде шлюза, стенда и в `docs/` нет незакоммиченных правок. Правки в других файлах (презентация, заметки) цикл не тронет и в коммиты не возьмёт.
4. **Образец на месте**: `prototype/rescan-app-standalone.html`. Если файла нет, положите его туда сами: файл вне папки проекта Claude Code прочитает только после вашего разрешения, и цикл будет ждать ответа.
5. **Решения владельца** в начале каждого задания: прочитайте и поправьте до запуска. Главные из них:
   - шрифт Stolzl коммерческий, поэтому он и образец не попадают в git; на машине без файла шрифта кабинет показывается системным шрифтом (12);
   - из меню врача и пациента уходят экраны, данные которых живут в памяти вкладки («Связь с клиникой», «Сообщения», «Аптека», «Новое обращение»), и «Карта сервисов»: она остаётся у координатора и партнёра (12, 13);
   - аптека работает на сервисе медикаментов, отметки приёма (этап Б) выключены (14).

## Как открыть Claude Code

В корне репозитория:

```
claude --permission-mode auto --disallowedTools "Bash(git push *)" "PowerShell(git push *)"
```

- `--permission-mode auto` — автоматический режим: команды проверяет классификатор, а не вы. В ручном режиме цикл будет ждать вашего ответа на каждую команду. Режим можно сменить и в сессии: Shift+Tab до надписи `auto mode on`.
- `--disallowedTools …` — запрет на отправку. В автоматическом режиме push в ветки своего репозитория разрешён по умолчанию. Фразу «не пушь» из промта классификатор тоже учитывает, но правило запрета проверяет сам Claude Code, и оно не зависит от того, что осталось в разговоре.

Правило ловит команду, которая начинается с `git push`. Другое написание, например `git -C . push`, под него не попадает. Чтобы отправка в `origin` не прошла ни в каком написании, отключите её в самом git на время работы циклов:

```
git remote set-url --push origin no-push
```

Вернуть как было: `git config --unset remote.origin.pushurl`.

Чтобы не указывать запрет при каждом запуске, создайте `.claude/settings.local.json` в корне репозитория. Файл личный: в git его не добавляйте.

```json
{
  "permissions": {
    "deny": [
      "Bash(git push *)",
      "PowerShell(git push *)"
    ]
  }
}
```

## То же без пауз: /goal

`/goal` начинает следующий ход сразу после предыдущего. Готовность проверяет отдельная модель, и видит она только то, что показано в разговоре. Поэтому в условии сказано, что именно нужно показать. Для задания 12:

```
/goal В docs/reports/12-rescan-doctor.md все циклы задания prompts/12-rescan-doctor.md и «Финал» отмечены [x], и в разговоре показаны раздел «Ход работ» и вывод полной проверки без ошибок: OK у пяти наборов unittest, строка «Смоук-проверка пройдена» и строка «Проверка в браузере: N из N», где оба числа равны. Работай по правилам prompts/rescan-loop.md, один цикл за ход, не пушь и не мержи. Условие также выполнено, если в «Ходе работ» записан СТОП без СНЯТО и эта строка показана в разговоре. Или остановись после 40 ходов.
```

Для заданий 13, 14 и 15 замените в условии номер и имя файла задания и отчёта. В задании 14 «Финал» — последний из выбранных этапов.

## Если цикл остановился

- **В «Ходе работ» строка `СТОП`.** Прочитайте причину, примите решение, допишите под ней `СНЯТО: решение` и вставьте ту же строку запуска.
- **Автоматический режим отклонил действие.** Claude Code покажет уведомление, а отклонённое действие появится в `/permissions` на вкладке Recently denied. После трёх отказов подряд или двадцати за сессию он вернётся к вопросам и будет ждать вашего ответа.
- **Остановить самим.** `/loop`: клавиша Esc, пока цикл ждёт следующего запуска. `/goal`: команда `/goal clear`.
- **Сессия закрыта или перезапущена.** Цикл `/loop` без интервала сам не восстановится. Вставьте ту же строку: он продолжит с первого незакрытого цикла.
- **Команды `/loop` или `/goal` нет.** Обновите Claude Code: `claude update`.

## Между заданиями

Прочитайте отчёт, посмотрите `git log` и дифф, откройте стенд (`python start.py`) и пройдите руками то, что обещано в «Готово, когда». Перед следующим заданием остановите стенд и начните новую сессию. Если отключали отправку в git, верните её перед тем, как делиться веткой.
