# Задания для Claude Code

Десять заданий, которые по шагам превращают прототип `prototype/medmarshrut_product_prototype_v2.html` в продукт на трёх настоящих сервисах: снимков, пути и клиники. Общий контекст и правила лежат в `CLAUDE.md` в корне: Claude Code читает его сам в начале каждой сессии. Контракты сервисов — в `docs/api-contracts.md`.

## Как пользоваться

1. Откройте терминал в корне репозитория и запустите `claude`.
2. Напишите: `Выполни задание из prompts/01-stand.md`.
3. Когда закончит, прочитайте отчёт в `docs/reports/`, посмотрите дифф и выполните проверки из раздела «Готово, когда» в файле задания.
4. Перед следующим заданием очистите контекст командой `/clear`.

Большое задание (03–07) удобно начинать с плана: «Прочитай prompts/04-path.md и покажи план. Код пока не пиши». Поправить план дешевле, чем готовый код. Задание 04 самое крупное и разбито на три этапа: их можно запускать по одному — «Выполни этап 1 из prompts/04-path.md».

- После 04 уже есть что показать: дизайн прототипа и ядро кейса на настоящем сервисе. Остальные экраны работают на данных вкладки, как в прототипе; кнопки, которые создавали бы маршрут в обход сервиса, отключены до своего задания.
- 07 можно пропустить. Тогда сообщения, аптека и запросы врачу живут в одном окне браузера и сбрасываются при обновлении страницы.
- Из 08 нужны хотя бы README и раздел ограничений.

## Что решено заранее

Эти решения заложены в задания. Не согласны — поправьте текст задания до запуска.

1. **Фронтенд — код прототипа, разложенный на модули.** Без React и сборки: дизайн переносится без потерь, Node не нужен, стиль совпадает с сервисами на стандартной библиотеке.
2. **Браузер ходит только в шлюз.** Сервисы слушают `127.0.0.1` без CORS, а их токены и секреты подписи нельзя отдавать в JavaScript.
3. **На стенде признаки на снимке заданы сценарием.** Обученной модели нет. Сценарный backend отдаёт заранее заданный признак только для учебных исследований; чужой снимок уходит на ручной разбор. Код сервиса снимков при этом не меняется, а в интерфейсе стоит плашка «демо-сценарий».
4. **Демо-правила и демо-сеть клиник лежат отдельно**, в `demo_stand/`. Поставляемые `rules.json` и `network.json` остаются как были.
5. **Герой сценария — КТ грудной клетки**, пока рентген не поддержан сервисами (задание 09).
6. **Три сервиса без бэкенда** («Врач — клиника», «Клиника — пациент», аптека) и расписание живут модулями в шлюзе и подписаны как демо.
7. **Шлюз не делает за врача его работу.** План, итог приёма и подтверждение заключения отправляются только из сессии врача.
8. **У каждой роли своя сессия.** Пациента, координатора, врача и партнёра можно открыть в соседних вкладках одного браузера: так удобнее показывать.

## О чём предупредить команду

Правки в чужих сервисах маленькие, но они есть. Список — в колонке «Чужой код» выше. Две вещи стоит обсудить с авторами заранее:

- сервис пути: время подтверждённой записи сменить нельзя, только отменить, после чего обращение возвращается врачу. Задание 04 это ограничение не обходит и предлагает добавить переход для переноса;
- сервис снимков: врач не может подтвердить исследование, в котором модель ничего не нашла или которое не прошло проверку. Такое исследование не попадает в маршрут. Задание 05 показывает его координатору отдельной группой, но заключение врача по нему ввести некуда.
