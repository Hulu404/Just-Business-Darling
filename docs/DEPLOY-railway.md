# Деплой демо-стенда на Railway

Как выложить МедМаршрут на Railway, чтобы показать его по ссылке. Данные только синтетические.

## Что разворачивается

Один сервис Railway запускает `python start.py` — тот же демо-стенд, что и локально: пять процессов в одном контейнере (сервисы пути, клиники, снимков, медикаментов и шлюз). Наружу открыт только **шлюз** — он слушает `0.0.0.0` на порту из `$PORT`, который задаёт Railway. Остальные четыре сервиса остаются на `127.0.0.1` внутри контейнера, как и требует правило «браузер ходит только в шлюз».

Базу PostgreSQL шлюз берёт **из существующего Supabase** — того же, что в локальном `.env`. Свой Postgres от Railway не подойдёт: шлюз требует `sslmode=require` и проверяет `GATEWAY_SUPABASE_PROJECT_REF` против строки подключения.

При каждом старте стенд готовит и наполняет схему заново (миграции + учебные случаи), поэтому демо всегда в одинаковом чистом состоянии.

## Что нужно заранее

- Аккаунт Railway и этот репозиторий на GitHub (Railway деплоит из ветки) **или** Railway CLI.
- Рабочие значения из локального `.env`: `GATEWAY_DATABASE_URL`, `GATEWAY_DB_SCHEMA`, `GATEWAY_SUPABASE_PROJECT_REF`. Их берём из своего `.env` и вставляем в переменные Railway руками — `.env` в git не попадает.

## Шаги

1. **Создайте проект.** Railway → *New Project* → *Deploy from GitHub repo* → выберите репозиторий и ветку. Сборщик (`NIXPACKS`), команду запуска (`python start.py`) и healthcheck `/api/health` Railway возьмёт из `railway.json`, зависимости — из корневого `requirements.txt`.

2. **Задайте переменные** (*Service → Variables*). Скопируйте из своего `.env`:

   | Переменная | Откуда | Обязательна |
   |---|---|---|
   | `GATEWAY_DATABASE_URL` | `.env` (Supabase, с `sslmode=require`) | да |
   | `GATEWAY_DB_SCHEMA` | `.env`; для демо лучше отдельное имя, например `gateway_railway` | да |
   | `GATEWAY_SUPABASE_PROJECT_REF` | `.env` (ref проекта Supabase) | да |
   | `ANTHROPIC_API_KEY` | ваш ключ Claude | нет — только если нужен ИИ-помощник |
   | `GATEWAY_ASSISTANT_MODEL` | напр. `claude-sonnet-5-5` | нет |

   `PORT` Railway задаёт сам — вручную не добавляйте. Межсервисные секреты стенд генерирует на каждом запуске, задавать их не нужно.

   Отдельная схема (`gateway_railway`) рекомендуется, чтобы деплой не перетирал схему, с которой вы работаете локально: стенд на старте сбрасывает и наполняет свою схему заново. Миграции создадут новую схему сами.

3. **Откройте домен.** *Service → Settings → Networking → Generate Domain*. Порт определяется автоматически: шлюз слушает `$PORT`. Первая загрузка занимает ~30–60 секунд (поднимаются пять процессов, идут миграции и наполнение) — healthcheck ждёт до 300 секунд.

4. Перейдите по выданному адресу — откроется приложение. Роли переключаются списком «Режим просмотра»; врач попадает в кабинет rescan, пациент и координатор — в свои экраны.

## Что поменялось в коде ради деплоя

Локальный запуск при этом не изменился: правки включаются только когда Railway задаёт `$PORT`.

- `medmarshrut_gateway_service/service.py` — адрес привязки шлюза берётся из `GATEWAY_BIND` (по умолчанию `127.0.0.1`; на Railway `0.0.0.0`).
- `start.py` — если задан `$PORT`, шлюз запускается на нём и на `0.0.0.0` (`PUBLIC_PORT`/`PUBLIC_BIND`); четыре внутренних сервиса всегда на `127.0.0.1`.

## Ограничения демо

- Только синтетические данные: реальных пациентов, DICOM и секретов здесь нет.
- Состояние (SQLite сервисов пути/клиники/медикаментов) живёт в эфемерной файловой системе контейнера и теряется при перезапуске — это нормально, стенд наполняется заново.
- Схема шлюза в Supabase сбрасывается и наполняется при каждом старте. Не используйте для Railway ту же схему, что и для текущей локальной работы.
- ИИ-помощник выключен, пока не задан `ANTHROPIC_API_KEY`.
- Сборка ставит сценарный backend снимков. Для настоящей модели (`--image real`) нужен `onnxruntime` и другой запуск — в этот деплой не входит.

## Если не поднимается

- **Healthcheck не проходит.** Посмотрите логи деплоя: обычно это неверный `GATEWAY_DATABASE_URL` (нужен `sslmode=require`) или несовпадение `GATEWAY_SUPABASE_PROJECT_REF` со строкой подключения.
- **Ошибка версии Python** при сборке numpy/pydicom — задайте переменную `NIXPACKS_PYTHON_VERSION=3.12`.
- **«Порт занят»** в логах локально, но не на Railway: это проверка стенда; на чистом контейнере портов хватает.
