## Часть А. Тип `xray` в сервисе пути и сервисе клиники

**Что сделано**

- Сервис пути принимает правила и заключения с `study_type: "xray"`.
- Сервис клиники принимает сеть с возможностью `xray` и находит по ней кандидатов маршрута.
- Стенд: в `rules.demo.json` — область `xray` / `CHEST` / `CHEST_PA` и утверждённое правило `DEMO_XR_INFILTRATE` с шагом `appointment` «Приём терапевта в течение 24 часов»; в `network.demo.json` — эта область у `clinic-central`.
- Объяснение для пациента `DEMO_XR_INFILTRATE` (тексты `seen` и `means` рентгенографии из прототипа) — в `medmarshrut_gateway_service/catalog.py`, `FINDING_TEXTS`; наполнение кладёт его в таблицу `finding_texts`. Файла `patient_texts.demo.json`, который называет задание, в репозитории нет: объяснения с задания 04 живут в каталоге шлюза, решение согласовано с владельцем задания.
- Шлюз и экраны: вид исследования показывается по-русски — `views.study_title` (название по типу и области, иначе «КТ», «МРТ», «Маммография», «Рентгенография»), карточка обращения, «Маршруты и правила» и песочница правил. Раньше на этих экранах был сырой код (`ct`). Песочница предлагает область рентгена из файла правил.
- Документация: список типов в README сервиса пути и в `docs/api-contracts.md`. В README сервиса клиники списка типов нет (README обрывается, дописывается в задании 08).
- Смоук: шаг 20 «Песочница правил: рентген».
