# Исправления ревью rescan_core, 17.10.2026

Проверен коммит `bb3774c` (B1, B2, B3), исправлены десять замечаний ревью.
Изменения выполнены в ветке `mvp` по прямому поручению пользователя; интерфейс
и пять существующих сервисов МедМаршрута не изменялись.

## Что сделано

- Исходные тела событий больше не сохраняются; неизвестные поля отклоняются.
  Телефон остаётся только в зашифрованном контакте, ошибки API не отражают тело.
- Новая миграция `20261017_secure_ingest` очищает `events.raw_payload` и расширяет
  `audit_events.entity_id` с 64 до 128. Проверены upgrade старой базы и повторный upgrade.
- Timestamp включён в HMAC. Для CSV подписывается содержимое файла, без multipart.
  Файл читается один раз; ошибка `Stream consumed` устранена.
- Вне `local`/`test` обязательны отдельные секреты от 32 символов, безопасные
  служебные токены (или пустой словарь) и явный `MIS_CLINIC_ID`.
  Ошибки настройки не печатают значения секретов.
- Выключенная клиника получает 403 без записей в БД. Неоднозначная локальная
  конфигурация клиник получает 503, вместо произвольного выбора первой.
- Событие атомарно резервируется первым; справочники создаются через
  `ON CONFLICT DO NOTHING`. Контакт и группа сериализуются блокировкой пациента.
  При сбое вся транзакция откатывается, повтор можно принять заново.
- CSV сохраняет валидные визиты транзакционно, точные повторы не дублируются.
  Суммы проверяются через Decimal и переводятся в копейки без float.
- Workflow перенесён в корень `.github/workflows/rescan-core.yml`, настроены
  рабочая папка, lint, mypy, миграции, тесты SQLite и PostgreSQL.

## Проверки

В `rescan_core`:

```text
python -B -m pytest -p no:cacheprovider
python -B -m ruff check .
python -B -m mypy app
python -B -m alembic upgrade head
python -B -m alembic check
```

Для повторного прогона на PostgreSQL задаётся `RESCAN_TEST_DATABASE_URL` на
отдельную тестовую базу. Каждый тест создаёт и удаляет собственную схему.
Локально использован временный PostgreSQL 18.1; CI использует PostgreSQL 16.

- SQLite: 56 тестов.
- PostgreSQL: 56 тестов, включая четыре одновременных запроса, максимальный
  event_id, миграцию с открытым телом, откат неуспешной транзакции и повторный CSV.
- Пять существующих сервисов: снимки 20, путь 12, клиника 8, медикаменты 10,
  шлюз 108. Шесть PostgreSQL-тестов шлюза отдельно выполнены на временной БД.
- `python start.py --smoke`: 22/22 на отдельной локальной схеме и синтетических данных.
- Ruff, mypy, `alembic check`: без ошибок и расхождений модели с миграциями.

## Обновление и ограничения

1. До запуска обновлённого сервера выполните `python -m alembic upgrade head`.
   Очистка raw_payload необратима. Существующие резервные копии миграция не очищает.
2. Обновите отправителей: HMAC теперь считается от `timestamp + "." + content`.
   Старый вариант намеренно не поддерживается, иначе обход TTL останется.
3. В production задайте секреты и `MIS_CLINIC_ID`; ненужные staff-токены отключите `{}`.
4. Контракт CSV пока не содержит visit_id. Повтор определяется по нормализованным
   значениям всех четырёх колонок. Два одинаковых визита неразличимы, изменение суммы
   создаёт новую строку. Предложение команде: согласовать внешний visit_id для обновлений.
5. Даты CSV без смещения для совместимости трактуются как UTC. Новые выгрузки должны
   указывать часовой пояс; это явно описано в контракте.
6. API-ключ, переданный в контекст IDE, требует отзыва у провайдера. Эти изменения
   его не отзывают и не заменяют; `.env` не изменялся и не включён в коммит.
