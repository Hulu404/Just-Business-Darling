# 06. Карта пациента, партнёры и направления на настоящем сервисе

## Что сделано

Карточка обращения, экран «Партнёры», «Документы» пациента, блок «Клиника» в «Аналитике» и новый кабинет клиники-партнёра работают на `medmarshrut_clinic_service` через шлюз. Демо-данные партнёров и направлений (`PARTNERS`, `state.referrals`, `REF_FLOW`, `upsertReferral`, `advanceReferral`) удалены.

**Сервис клиники** (правки в чужом коде — ниже отдельными строками)

- `GET /v1/referrals?status=` для сотрудника: направления, где его клиника — отправитель или получатель. К каждому направлению добавлен только `patient_ref`, ничего больше о пациенте.
- `GET /v1/patients` с неверными `limit` или `status` отвечает 400, а не обрывает соединение.

**Шлюз**

- Миграция `003_referral_links.sql`: `referral_id` (ключ), `episode_id`, `step_id`, `created_by`, `created_at`, RLS без клиентских политик. Чистый `start.py` очищает её вместе с рабочими таблицами, `--keep` сохраняет, каталог (`seed_catalog`) её не трогает.
- Маршруты: `GET /api/staff/patients`, `GET /api/staff/patients/{patient_ref}/card`, `POST /api/staff/patients/{patient_ref}/anamnesis`, `GET /api/staff/episodes/{id}/route-candidates`, `POST /api/staff/episodes/{id}/steps/{step}/referral`, `GET /api/staff/referrals`, `POST /api/staff/referrals/{id}/cancel`, `GET /api/staff/network`, `GET /api/partner/queue`, `GET /api/partner/referrals`, `GET /api/partner/patients/{id}/card`, `POST /api/partner/referrals/{id}/{accept|reject|complete}`, `GET /api/patient/documents`. Роли и подробности — в README шлюза.
- Токен к сервису клиники выбирается по клинике сессии (`_own_clinic`): сессия сотрудника — только своя клиника, сессия партнёра — только своя клиника-партнёр. `author_id`, `author_role`, `clinic_id`, `from_clinic_id`, `created_by` и `actor` берутся из сессии.
- `route-candidates`, `referrals` и `by-ref` подписываются `CLINIC_SHARED_SECRET`. Причины без кандидатов переведены: «Пациент не найден в карте клиники», «Карта пациента закрыта», «Ни своя клиника, ни партнёры не выполняют такой шаг». Конфликты 409: «Направление этому партнёру уже есть…», «Клиника не входит в число действующих партнёров…», «Направить можно только активного пациента…».
- Направление и связь: если сервис клиники принял направление, а запись связи не удалась, шлюз отвечает 503 «Направление создано, но связь с шагом не записалась…». Повтор находит действующее направление той же пары клиник для пациента и дописывает связь — второго направления нет.
- Запись у партнёра: `POST /api/staff/episodes/{id}/steps/{step}/confirm` с `{"partner_time", "partner_clinic_id"}` — только при принятом направлении к этой клинике; шлюз делает `offer` и `confirm` с этим временем, в `evidence` — «Запись у партнёра: <клиника>».
- `complete` от партнёра не вызывает ни одного запроса к сервису пути: координатор отмечает визит сам, врач вносит итог.
- `/api/health` отдаёт `partner_clinics` — клиники-партнёры с токеном и человеком на стенде, для списка ролей.
- Сопоставление маршрутов теперь выбирает самый конкретный шаблон: `…/steps/{step}/referral` не перехватывается общим `…/steps/{step}/{action}`.

**Интерфейс** (`web/js/clinic-ui.js`)

- Карточка обращения: блок «Пациент по карте клиники» (ФИО, возраст, «Учтено из карты»: диагнозы, факторы риска, аллергии; у записей `shareable: false` — «только для своей клиники»), блок «Где выполнить шаг» (кандидаты: своя клиника «у нас», партнёр «нужно направление», кнопка «Направить к партнёру», статус направления, «Если нет времени»), список направлений пациента со строкой «Партнёр сообщил: услуга оказана», кнопка «Записать время у партнёра», запись в анамнез (вид, текст, «Показывать партнёрам»).
- «Партнёры»: «Клиники-партнёры» — карточки из сети с «Направлено» и «Принято партнёром» по настоящим направлениям, без «Обмена данными» и «До записи»; «Направления» — таблица со статусами и «Отменить» для `proposed` и `accepted`, пациент — ссылка на карточку, если есть связь с шагом; «Аптеки-партнёры» — демо до задания 07.
- Роль «Клиника-партнёр»: пункты «Партнёр: Диагностический центр на Лесной» и «Партнёр: Маммологический центр «Опора»» в «Режиме просмотра», адрес `#/partner/incoming?clinic=…`. «Входящие направления» и карточка направления: до принятия — псевдоним, домашняя клиника, доступные записи анамнеза и «ФИО и контакт откроются после принятия направления»; «Принять» и «Отклонить» с комментарием; у принятого — «Услуга оказана»; после принятия — ФИО, дата рождения, пол, контакт.
- «Документы» пациента: раздел «Направления» (куда, зачем, статус).
- «Аналитика»: блок «Клиника» — пациентов на сопровождении, направлено партнёрам, принято партнёрами.
- «Карта сервисов»: переход «Глазами партнёра» в карточке «Путь пациента».

**Стенд**

- Смоук: 19 шагов. Новые: кандидаты и направление через шлюз → партнёр видит карту без ФИО и внутренних записей → принимает → видит ФИО → координатор записывает время партнёра → партнёр завершает (эпизод в сервисе пути не меняется) → направление «Услуга оказана» со связью с шагом → координатор отмечает визит. В шаг маммографии добавлена проверка кандидатов: своя клиника и «Опора».
- `web_check.py`: роль партнёра в обходе экранов, «Партнёры», «Документы» и «Входящие направления» убраны из попиксельного сравнения, новый сценарий: окна координатора и партнёра рядом, направление Олега Р. без ФИО до принятия, время партнёра, «услуга оказана», визит.

## Ограничения

- Расписаний партнёров нет: время у партнёра координатор вводит со слов партнёра (появится в задании 07). В таблицу записей шлюза (`appointments`) такая запись не попадает, она есть только в шаге сервиса пути.
- Связь направления с шагом есть только у направлений, созданных через шлюз. Направление Олега Р. из наполнения создано напрямую в сервисе клиники и показывается «без связи с шагом».
- Кука роли партнёра одна: в одном браузере одновременно открыта одна клиника-партнёр, окно другой клиники открывает свою сессию заново.
- Адрес `#/staff/case` не хранит выбранное обращение: после перезагрузки карточка открывает первое обращение списка (так было и в задании 04).
- `GET /v1/patients` ограничен 500 пациентами клиники: поиск `id` по псевдониму в шлюзе работает только в этих пределах.
- Карта партнёра строится сервисом по последнему направлению; после `completed` партнёр видит ФИО бессрочно, новое `proposed` снова скрывает (поведение сервиса, см. `docs/api-contracts.md`).
- Партнёру шлюз добавляет к направлениям только названия клиник из того же сервиса клиники (`GET /v1/clinics` с токеном партнёра) — других источников нет.

## Чего сервису клиники не хватает для экранов

- Возможностей клиник в API: что умеет партнёр, сейчас видно только в файле сети, поэтому в карточке партнёра нет списка услуг.
- Сроков ожидания у партнёров и их расписаний: строку «До записи» пришлось убрать.
- Истории решений по направлению: `decided_at`, `decided_by`, `decision_note` перезаписываются, комментарий к принятию пропадает после `complete`.
- Поиска пациента по `patient_ref` для сотрудника (сейчас — перебор списка до 500).
- Списка направлений с фильтром по пациенту.
