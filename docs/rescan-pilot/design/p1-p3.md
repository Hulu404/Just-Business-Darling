# Каркасы и тексты P1–P3 и входа сотрудника

Задание 18, дизайнер. Токены — `web/pilot/css/tokens.css`, тема клиники — `theme-system.md`.

Как читать: каркас — блоки экрана сверху вниз, в квадратных скобках ключ текста. Сами тексты — в разделе «Тексты» одним JSON: его можно положить в `texts` мока как есть. Если текст в каркасе и в JSON разошёлся, верен JSON.

## Подстановки

| Метка | Откуда | Как выводить |
|---|---|---|
| `{clinic_name}` | `clinic.name` | через `safe()`, без своих кавычек |
| `{clinic_phone}` | телефон клиники (поля в контракте пока нет, см. вопросы) | через `safe()`; ссылка `tel:` из цифр и `+` |
| `{doctor_name}` | `doctor_step.doctor_name` | через `safe()`; `null` — строку не показываем |
| `{weeks_text}` | `doctor_step.retest_weeks` + форма слова из `p2.retest.weeks.*` | см. ниже |
| `{n}` | число недель | — |
| `{display_name}` | ответ мок-входа | через `safe()` |

Название клиники в предложения не вставляем: оно не склоняется («позвоните в Клиника Здоровье»). Клиника видна в шапке.

Форма слова «неделя» после «через»: `n % 10 == 1 && n % 100 != 11` — `one` («через 1 неделю»), `n % 10` от 2 до 4 и `n % 100` не от 12 до 14 — `few` («через 2 недели», «через 4 недели»), иначе `many` («через 8 недель», «через 12 недель»).

## Общий каркас пациента

```
┌ шапка 56 px, --surface, линия --line снизу ───────────┐
│ [логотип или {clinic_name}]                [shell.demo_badge] │
└────────────────────────────────────────────────────────┘
  колонка --col 560 px по центру, поле --gutter 16 px
  #view — экран
  подвал: [shell.footer]
```

- Заголовок экрана — `h1`, `--fs-title`, `--fw-bold`. Один `h1` на экран.
- Основная кнопка — во всю ширину колонки, `--btn-h`, заливка `--clinic-accent`, текст `--clinic-on-accent`. На экране одна основная кнопка.
- Варианты выбора (ветки, цели) — `fieldset` с `legend` = заголовок экрана, внутри `input type="radio"` и подпись-строка во всю ширину: `--surface`, рамка 1 px `--line-input`, `--r-row`, высота не меньше `--tap`. Выбранный: рамка 2 px `--clinic-accent`, фон `--clinic-accent-soft`, галочка справа. Стрелки меняют выбор, Tab переходит к кнопке.
- Заметка и ошибка — блок `--note-bg`, `--r-row`, текст `--fg`, `role="status"` для заметки и `role="alert"` для ошибки отправки. Без красного и без значка «!».
- Загрузка — `.card.skeleton` (её ждёт `web_check.py`) и скрытый текст `[shell.loading]` с `aria-live="polite"`.
- `document.title` — `[shell.title]`.

## P1. Вход по ссылке — `#/p/<token>`

### `active`, согласие уже есть

```
h1 [p1.active.title]
p  [p1.active.body]
кнопка [p1.active.action]                → go(#/p/<token>/step)
заметка [p1.active.privacy]
```

### `active`, `consent_required: true` (токен `demo-consent`)

```
h1 [p1.consent.title]
p  [p1.consent.body]
p  [p1.consent.revoke]
ссылка [p1.consent.policy_link]          → адрес политики клиники; нет адреса — ссылку не показываем
кнопка [p1.consent.action]               → POST /patient/consent → go(#/p/<token>/step)
   во время запроса текст кнопки [p1.consent.pending], кнопка недоступна
   ошибка запроса: заметка-ошибка [p1.consent.error] над кнопкой, кнопка снова доступна
```

Отдельного «Не соглашаюсь» нет: можно просто закрыть страницу. Галочки «Я согласен» нет — нажатие кнопки и есть согласие; текст согласия утверждает юрист клиники до КТ2.

### `expired` (токен `demo-expired`)

```
h1 [p1.expired.title]
p  [p1.expired.body]
кнопка-ссылка tel: [p1.call.action]      есть телефон
p  [p1.call.no_phone]                     нет телефона (вместо кнопки)
```

### `stopped` (токен `demo-stopped`)

```
h1 [p1.stopped.title]
p  [p1.stopped.body]
кнопка-ссылка tel: [p1.call.action] / p [p1.call.no_phone]
```

### `unsubscribed` (токен `demo-unsubscribed`)

```
h1 [p1.unsubscribed.title]
p  [p1.unsubscribed.body]
кнопка-ссылка tel: [p1.call.action] / p [p1.call.no_phone]
```

Во всех трёх закрытых состояниях нет кнопки «повторить», нет переходов дальше, нет шага врача и целей, даже если они пришли в ответе.

### Оболочка (до ответа сервиса, тексты у фронтенда)

```
загрузка:           .card.skeleton ×2 + [shell.loading] для чтения с экрана
ошибка сервиса:     h1 [shell.error.title] / p [shell.error.body] / кнопка [shell.error.action] → перезагрузить экран
нет такого адреса:  h1 [shell.not_found.title] / p [shell.not_found.body]
```

## P2. Шаг врача или три ветки — `#/p/<token>/step`

### Врач отметил шаг

```
p.label [p2.doctor.label]                 --fs-s, --fg-2
p       {doctor_name}                     --fs-l, --fw-medium; нет имени — обе строки не показываем
h1      [p2.<code>.title]                 code = discuss | retest | followup
p       [p2.<code>.body]
кнопка  [p2.step.action]                  → go(#/p/<token>/goal), branch_code = null
```

Токены: `demo-step-discuss`, `demo-step-retest`, `demo-step-followup`. Шаг врача — карточка `--surface` без цветной полосы, без значков и без даты-срока.

### Врач шаг не отметил (токен `demo-active`)

```
h1      [p2.branches.title]               это же legend у fieldset
p       [p2.branches.body]
radio   branches[0]: [p2.branch.<code>.title] / мелко [p2.branch.<code>.hint]
radio   branches[1]
radio   branches[2]
кнопка  [p2.branches.action]              недоступна, пока ничего не выбрано
p       [p2.branches.choose]              под кнопкой, --fg-2, пока ничего не выбрано
                                          → go(#/p/<token>/goal), branch_code = выбранный
```

Ветки приходят в `branches` как `[{ code, title, hint }]`; `title` и `hint` в моке — тексты из JSON ниже. Порядок — как в ответе, первый вариант не выбран заранее.

## P3. Цель визита — `#/p/<token>/goal`

```
ссылка  [p3.back]                         → go(#/p/<token>/step)
h1      [p3.title]                        legend у fieldset
p       [p3.body]
radio ×4 goals[i].title                   данные из goals, порядок как в ответе
кнопка  [p3.action]                       недоступна, пока цель не выбрана
p       [p3.choose]                       пока цель не выбрана
   запрос POST /patient/choice { branch_code | null, goal_id }:
   во время запроса — [p3.pending], кнопка недоступна
   успех → go(#/p/<token>/next)
   ошибка → заметка-ошибка [p3.error] над кнопкой, выбор сохраняется
```

Цели в моке (`goals`, тексты из настроек клиники):

| id | title |
|---|---|
| `goal-discuss` | Обсудить анализы с врачом |
| `goal-retest` | Пересдать анализы |
| `goal-followup` | Повторный приём у своего врача |
| `goal-other` | Другой вопрос к врачу |

## Заглушка — `#/p/<token>/next`

```
h1      [next.title]
p       [next.body]
заметка [next.saved]
ссылка  [next.back]                       → go(#/p/<token>/goal)
```

## Вход сотрудника — `#/staff/login`

Тема клиники не применяется, акцент наш.

```
шапка: «rescan» текстом слева ............ [shell.demo_badge]
колонка --col-staff 420 px, карточка --surface
h1     [staff.login.title]
p      [staff.login.subtitle]
поле   label [staff.login.login]          input type=text, autocomplete=username, autocapitalize=off
поле   label [staff.login.password]       input type=password, autocomplete=current-password
заметка-ошибка                             одна из: [staff.login.empty] | [staff.login.wrong] | [staff.login.unavailable]
кнопка [staff.login.action]               Enter в любом поле отправляет форму
       во время запроса [staff.login.pending], кнопка недоступна
заметка [staff.login.demo_hint]
```

- Неверный логин: пароль очищается, фокус — в поле пароля, логин остаётся.
- Пустые поля: запрос не отправляем, показываем `staff.login.empty`, фокус — в первое пустое поле.
- Ошибка ссылается на поля через `aria-describedby`.

### `#/doctor` и `#/clinic`

```
шапка: «rescan» ....... {display_name} · [staff.role.<role>] · кнопка [staff.logout] · [shell.demo_badge]
h1 [staff.doctor.title]  | [staff.clinic.title]
заметка [staff.doctor.stub] | [staff.clinic.stub]
```

Чужая роль (врач открыл `#/clinic`) или вход не выполнен:

```
h1 [staff.forbidden.title]
p  [staff.forbidden.body]
кнопка [staff.forbidden.action]           → go(#/staff/login)
```

## Решения и что ждёт подтверждения

- Коды веток совпадают с кодами шагов врача: `discuss`, `retest`, `followup`. Это предложение для черновика B6, коды подтверждает бэкенд.
- Цели — четыре нейтральные формулировки выше. В `seed_demo.py` сейчас другие («Обсудить результат с врачом», «Повторный анализ через время», «Контрольный приём», «Другое»); предлагаю заменить на эти при работе над B6.
- Ветка выбирается на P2, а уходит на сервер вместе с целью в `POST /patient/choice` на P3. Как P3 узнаёт выбранную ветку, решает фронтенд (состояние в памяти вкладки, без `localStorage`).
- Тексты согласия — черновик: их утверждают клиника и юрист до КТ2.
