# Каркасы и тексты P4–P8 и ошибок пациента

Задание 19, дизайнер. Продолжение `p1-p3.md`: общий каркас пациента, правила кнопок, вариантов выбора, заметок и загрузки — оттуда, здесь не повторяются. Токены — `web/pilot/css/tokens.css`, тема клиники — `theme-system.md`.

Как читать: каркас — блоки экрана сверху вниз, в квадратных скобках ключ текста. Сами тексты — в разделе «Тексты» одним JSON: его можно положить в `texts` мока и в `patient_settings.texts` как есть. Если текст в каркасе и в JSON разошёлся, верен JSON.

## Подстановки

| Метка | Откуда | Как выводить |
|---|---|---|
| `{clinic_phone}` | `clinic.phone` | как в P1: `contact()` из `patient-common.js` |
| `{doctor_name}` | `doctor_step.doctor_name`, `request.doctor_name`, `after_visit.step.doctor_name` | через `safe()`; `null` — строку с подстановкой не показываем |
| `{price}` | `price_kopecks` формата | см. «Цена» ниже |
| `{date}` | `doctor_step.due_date`, `after_visit.step.due_date`, `request.created_at` | см. «Дата» ниже |

**Цена.** Рубли = `price_kopecks / 100`. Разряды через неразрывный пробел, перед `₽` тоже неразрывный пробел: `250000` → «2 500 ₽», `90000` → «900 ₽», `150050` → «1 500,50 ₽» (копейки только если не ноль). Только для `currency = "RUB"`. Другая валюта, `null` или `0` — строку цены не показываем, «0 ₽» и «бесплатно» не пишем (см. вопросы).

**Дата.** День числом и месяц в родительном падеже: «17 ноября». Если год не текущий — с годом: «17 января 2027». Без дня недели, без «г.». Месяцы: января, февраля, марта, апреля, мая, июня, июля, августа, сентября, октября, ноября, декабря. `due_date` — дата без времени (`YYYY-MM-DD`), разбирать без перевода в пояс браузера, иначе дата съедет на день. `created_at` — дата в поясе браузера.

**Инициалы.** Первые буквы первых двух слов `name`, заглавными: «Иванова Анна Петровна» → «ИА». Одно слово — одна буква. Кружок `--avatar` (56 px), фон `--tag-bg`, буквы `--fg-2`, `--fs-l`, `aria-hidden="true"`: имя врача и так написано рядом.

**Фото.** Только если `photo_url` начинается с `/assets/` (то же правило, что у логотипа). Иначе инициалы. `alt=""`: имя рядом. Ошибка загрузки (обработчик в JS) — заменить на инициалы.

## P4. Выбор врача — `#/p/<token>/doctors`

Загружаются `GET /patient/doctors` и `GET /patient/formats` вместе. Пока ждём — `.card.skeleton` ×3 и `[shell.loading]`. Если в сессии есть `request` — сразу `go(#/p/<token>/status)`, экран не рисуем.

### Есть врачи (токены `demo-step-discuss`, `demo-active`)

```
ссылка  [p4.back]                         → go(#/p/<token>/goal)
h1      [p4.title]
p       [p4.body]                         --fg-2
список карточек, порядок как в ответе, ul без маркеров, промежуток --sp-3:
┌ карточка --surface, --r-row, рамка 1 px --line-input, вся карточка — одна кнопка ┐
│ [фото или инициалы]  name                     --fs-l, --fw-medium              │
│                      specialty                --fs-s, --fg-2                   │
│                      [p4.tag.ordering] | [p4.tag.visited]   метка, если tag    │
│                      [p4.price_from]          --fs-s, --fg                      │
│                                           [p4.card.action] ›   текст акцентом │
└──────────────────────────────────────────────────────────────────────────────┘
                                          → go(#/p/<token>/request?doctor=<id>)
```

- Карточка — `<a href>` на адрес P5 (или `button`), высота не меньше `--tap`, фокус — кольцо вокруг всей карточки. Внутри нет других нажимаемых элементов.
- Доступное имя карточки: имя, специальность, метка, цена — в порядке чтения; «Выбрать» и стрелка `aria-hidden`.
- Метка — плашка `--tag-bg`, текст `--tag-fg`, `--fs-xs`, `--fw-medium`, `--r-pill`, отступы `--sp-1` × `--sp-2`. Не акцентом и без значков: метка сообщает факт, а не оценивает врача. `tag: null` — плашки нет. Одна метка на карточку.
- Цена «от» — наименьшая `price_kopecks` среди форматов из `GET /patient/formats` (формат с `0` или не `RUB` в расчёт не берём). Цена одна и та же на всех карточках: форматы общие для клиники. Нет ни одной цены — строку не показываем.
- Основной кнопки на экране нет: выбор врача и есть действие.

### Врачей нет (токен `demo-no-doctors`)

```
ссылка  [p4.back]                         → go(#/p/<token>/goal)
h1      [p4.empty.title]
p       [p4.empty.body]
кнопка-ссылка tel: [p1.call.action] / p [p1.call.no_phone]     contact()
ссылка  [p4.empty.change_goal]            → go(#/p/<token>/goal)
```

## P5. Формат, время, заявка — `#/p/<token>/request?doctor=<id>`

Врача ищем в `GET /patient/doctors` по `id`; форматы и окна — из `GET /patient/formats`. Если в сессии есть `request` — `go(#/p/<token>/status)`.

### Форма (токены `demo-step-discuss`, `demo-active`, `demo-paid-format`)

```
ссылка  [p5.back]                         → go(#/p/<token>/doctors)
h1      [p5.title]
карточка врача --surface, не нажимается:
        [p5.doctor.label]                 --fs-s, --fg-2
        [фото или инициалы] name / specialty
fieldset legend [p5.format.legend]
        radio formats[i]: title           --fs-body, --fw-medium
                          {price}         справа в той же строке, --fg; нет цены — пусто
                          [p5.format.prepay]   мелко под названием, только если has_payment
fieldset legend [p5.window.legend]
        p [p5.window.hint]                --fs-s, --fg-2, связан с fieldset через aria-describedby
        radio windows[i]: title
заметка [p5.confirm_note]                 role="status" не нужен, обычный блок --note-bg
область ошибки (feedback(), role="alert")  [err.invalid_input] | [p5.error]
кнопка  [p5.action]                       недоступна, пока не выбраны формат и окно
p       [p5.choose]                       под кнопкой, --fg-2, пока что-то не выбрано
   запрос POST /patient/requests { doctor_id, format_id, window_code }:
   во время запроса — текст кнопки [p5.pending], кнопка недоступна
   201 без payment_url → go(#/p/<token>/status)
   201 с payment_url  → состояние «Оплата» ниже
   422 → [err.invalid_input] в области ошибки, выбор не сбрасывается
   сеть → [p5.error] в области ошибки, выбор не сбрасывается, кнопка снова доступна
   остальное → handlePatientError
```

- Ни один вариант не выбран заранее, даже если формат или окно одно.
- Порядок форматов и окон — как в ответе. Формат с оплатой не выделяем: та же строка, что у остальных.
- Свободного ввода нет: ни комментария, ни телефона, ни «пожеланий».

### Оплата (токен `demo-paid-format`, после `201` с `payment_url`)

```
h1      [p5.paid.title]
p       [p5.paid.body]
кнопка-ссылка [p5.paid.action]            href = payment_url, target="_blank", rel="noopener noreferrer"
                                          основная кнопка экрана
p       [p5.paid.new_tab]                 --fs-s, --fg-2, под кнопкой
ссылка  [p5.paid.later]                   → go(#/p/<token>/status)
заметка [p5.paid.note]
```

Адрес оплаты показываем, только если он `https://`. Иначе сразу P6. После перехода на оплату экран остаётся: пациент вернётся во вкладку и нажмёт «Посмотреть заявку».

### Врача нет в списке (адрес с чужим или старым `doctor`)

```
h1      [p5.no_doctor.title]
p       [p5.no_doctor.body]
кнопка  [p5.no_doctor.action]             → go(#/p/<token>/doctors)
```

## P6. Заявка и её статус — `#/p/<token>/status`

Данные — `request` из сессии. Нет `request` — `go(#/p/<token>/doctors)`.

```
h1      [p6.<status>.title]               status = accepted | in_progress | booked | cancelled
p       [p6.<status>.body]
ol шаги (кроме cancelled):                 --fs-s
        [p6.progress.accepted]
        [p6.progress.in_progress]
        [p6.progress.booked]
   пройденный шаг — галочка цвета --fg-2 и текст --fg-2; текущий — --fw-bold, --fg,
   aria-current="step" и скрытый текст [p6.progress.current]; будущий — --fg-3
карточка заявки --surface, dl:
        [p6.summary.doctor]   doctor_name
        [p6.summary.format]   format_title
        [p6.summary.window]   window_title
        [p6.summary.created]  {date} из created_at
   поле null — строку dl не показываем
кнопка-ссылка tel: [p1.call.action] / p [p1.call.no_phone]     contact(); единственная кнопка
заметка [p6.revisit]
```

- Токены: `demo-request-accepted`, `demo-request-in-progress`, `demo-request-booked`, `demo-request-cancelled`; сразу после заявки — `accepted`.
- Цвет у статусов один и тот же. Нет зелёного «записан» и красного «закрыта», нет таймера «ждём звонка N минут», нет обещаний срока.
- `cancelled`: шагов нет, только заголовок, текст, сводка и звонок.

## P7. Пересдача — `#/p/<token>/retest`

Данные — `doctor_step` из сессии. Открывается кнопкой `[p7.entry]` на P2, когда врач отметил `retest` (вторая кнопка под `[p2.step.action]`, вид — текстовая кнопка, не основная).

```
ссылка  [p7.back]                         → go(#/p/<token>/step)
p.label [p2.doctor.label]                 как на P2; нет doctor_name — обе строки не показываем
```

- Токены: `demo-retest-before`, `demo-retest-today`, `demo-retest-overdue`.

## Ошибки пациента — `screens/patient-errors.js`

Разметка экранной ошибки: `h1` + `p` + кнопка или звонок, та же колонка, без значков и без красного. Ошибка у формы — заметка в `feedback()` над кнопкой, выбор сохраняется.

| Ошибка | Где | Каркас |
|---|---|---|
| `404 link_not_found` | экран | h1 `[err.link_not_found.title]` / p `[err.link_not_found.body]` / звонок, если телефон известен, иначе p `[err.call.no_phone]` |
| `409 not_active` | экран | P1 по свежей сессии (тексты `p1.expired.*`, `p1.stopped.*`, `p1.unsubscribed.*`) |
| `409 consent_required` | переход | `ctx.go` на P1, своего текста нет |
| `409 choice_required` | переход | `ctx.go` на P3, своего текста нет |
| `409 request_exists` | переход | `ctx.go` на P6, своего текста нет: заголовок P6 сам объясняет, что заявка уже есть |
| `422 invalid_input` | у формы | заметка `[err.invalid_input]` |
| `503 not_configured` | экран | h1 `[err.not_configured.title]` / p `[err.not_configured.body]` / звонок или `[err.call.no_phone]` |
| сеть, `status 0` | экран | h1 `[err.network.title]` / p `[err.network.body]` / кнопка `[err.network.action]` → повторить тот же запрос; во время повтора `[err.network.pending]` |
| сеть при отправке формы | у формы | заметка `[p5.error]` или `[p8.booked.error]` — экран не заменяем, чтобы не потерять выбор |
| прочие 5xx | экран | h1 `[err.server.title]` / p `[err.server.body]` / кнопка `[err.server.action]` → повторить |

Фокус после показа экранной ошибки — на `h1` (как `page()`), у формы — на область `feedback()`.

### Какие строки нужны до ответа сессии

`404 link_not_found`, `503 not_configured`, сеть и 5xx могут прийти на сам `GET /patient/session` — тогда `texts` сессии нет. Эти строки наши, клиника их не меняет. Фронтенд держит их в `texts.js` (`SHELL`) и берёт всегда оттуда, даже когда сессия загружена:

```
err.link_not_found.title, err.link_not_found.body,
err.not_configured.title, err.not_configured.body,
err.network.title, err.network.body, err.network.action, err.network.pending,
err.server.title, err.server.body, err.server.action,
err.call.no_phone
```

Звонок на этих экранах — только если телефон уже известен из ранее загруженной сессии; до сессии его нет, показываем `[err.call.no_phone]`. В `texts` сессии из ошибок приходит только `err.invalid_input`.

## Решения

**Цена быстрого ответа врача — как услуга клиники.** «Быстрый ответ врача» стоит в одном списке с остальными форматами на P5 и выглядит так же: название, цена справа, подпись «Оплата на сайте клиники после заявки». Без выделения, без «рекомендуем», без скидок, сроков и обещаний скорости. Название формата — от клиники, свою подпись о том, что врач ответит или когда, не добавляем: срок ответа обещает клиника, а не сервис. Оплата — на сайте клиники в новой вкладке, после заявки: заявка уже ушла, оплата её не задерживает, и пациент видит, что платит клинике, а не rescan. Наименьшая цена на P4 («от 900 ₽») честно получается из этого формата: цены на P5 стоят рядом с каждым форматом, так что «от» не вводит в заблуждение.

**Запись подтверждает администратор, а не система.** Слово «заявка» везде вместо «записи», пока клиника не подтвердила: кнопка «Оставить заявку», заголовок «Заявка принята». Заметка прямо над кнопкой на P5: «Это заявка, а не запись. Администратор клиники позвонит…» — пациент читает её до нажатия. На P6 тот же смысл в основном тексте и три шага «Заявка принята → Администратор подбирает время → Вы записаны»: видно, что «записаны» наступает позже и делает это человек. Время на P5 — «удобное время» с промежутком, а не слот в календаре: точного времени мы не знаем и не делаем вид, что знаем.

**Метки «Ваш врач» и «Вы уже были на приёме».** «Ваш врач» — у врача, назначившего анализы; те же слова пациент видел на P2 над именем врача, поэтому связь понятна без пояснений. «Вы уже были на приёме» — у врача, у которого есть визит. Метка — серая плашка, а не акцент и не значок: она говорит, откуда этот врач в начале списка, а не советует его. Порядок карточек пациенту не объясняем отдельным текстом. У врача одна метка; если назначивший врач — тот же, у кого пациент был, показываем «Ваш врач» (`tag` у него один по контракту).

**Красный акцент клиники, который проходит контраст.** Отсекать в `theme.js` по оттенку, так же тихо, как низкий контраст: акцент с оттенком HSL от 340° до 20° включительно и насыщенностью от 40% заменяется на наш `--rs-accent`, на `<html>` — `data-accent="fallback"`. Почему в коде, а не вручную: ручная проверка при подключении забывается и не повторяется, когда клиника меняет тему, а правило в коде проверяется тестом. Почему не «примерно красный» на глаз: граница должна быть одна для всех. Примеры: `#C62828` (контраст 5,63, оттенок 0°) — заменяется; `#B71C1C` — заменяется; `#8E2457` (оттенок 331°, малиновый) — остаётся; `#A0522D` (оттенок 19°, насыщенность 56%, кирпичный) — заменяется: на кнопке он читается как красный. Клиника с красным фирменным цветом узнаётся по логотипу и названию в шапке; при подключении мы предлагаем ей второй цвет из фирменного стиля, если он есть. Правило — для `theme-system.md` при следующей правке (сейчас файл не меняю) и для `theme.js` у фронтенда; тест — `demo-clinic-c` с `#C62828`.

**Прочее.**

- «У меня уже есть запись» вместо «Я уже записан» из контракта: не зависит от рода и короче на кнопке. Ответ — «Хорошо, напоминать не будем.», как в контракте.
- P7 «просрочено» не пишем нигде: в `overdue` заголовок «Записаться на пересдачу можно сейчас», дата — в тексте как факт.
- `request_exists`, `choice_required`, `consent_required` — переход без отдельного сообщения: экран, на который попадает пациент, сам объясняет ситуацию.
- Отдельной ссылки «Изменить заявку» на P6 нет: заявку меняет администратор по телефону.
- Токены: добавлены `--avatar`, `--tag-bg`, `--tag-fg` в `tokens.css`.

## Вопросы к продукту

1. По контракту P1 и P4 ведут на P6 при любой заявке в сессии, а `request_exists` бывает только при незавершённой. Значит, после `cancelled` или `booked` новую заявку через страницу оставить нельзя: P4 всегда уводит на P6. Предлагаю уводить на P6 только при `accepted` и `in_progress`, а на P6 в `cancelled` и `booked` дать текстовую кнопку «Оставить новую заявку» → P3. Сейчас в каркасе её нет — только звонок.
2. Формат с ценой `0` (по полису): показывать «по полису» или не показывать цену? Сейчас не показываем.
3. Окно времени для «Быстрого ответа врача» по смыслу — когда удобно получить ответ, а не прийти. Оставить одно поле «Удобное время» для всех форматов или скрывать окна у форматов без визита (нужен признак формата в B6)?
4. Название «Быстрый ответ врача» задаёт клиника. Слово «быстрый» обещает скорость, которую сервис не контролирует; предлагаю клиникам «Вопрос врачу онлайн». В `seed_demo.py` оставляю название из контракта.
5. Тексты памятки P7 о подготовке и документах — общие. Клиника может заменить их своими в `patient_settings.texts`; утвердить с клиникой до КТ2.
