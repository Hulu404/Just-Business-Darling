# Шлюз МедМаршрута

Шлюз раздаёт веб-приложение, держит сессии с ролями и сам ходит в сервисы снимков, пути и клиники. Браузер обращается только к шлюзу: токены и секреты сервисов остаются в процессе шлюза и в ответы не попадают.

Стандартная библиотека Python плюс `psycopg` (база PostgreSQL шлюза), `pydicom`, `numpy`, `Pillow` (заголовки DICOM и срезы в PNG) и `anthropic` (ИИ-помощник, задание 11), см. `requirements.txt`. Слушает `127.0.0.1:8763`.

```powershell
python -m pip install -r medmarshrut_gateway_service/requirements.txt
```

## Запуск

Обычно шлюз поднимает `python start.py` вместе с тремя сервисами. Ручной запуск из корня репозитория, когда сервисы уже работают:

```powershell
python start.py --print-secrets   # в другом окне; скопируйте строки $env:...
$env:GATEWAY_STATE_DIR = "$env:TEMP\medmarshrut-stand"
$env:GATEWAY_IMAGING_MODE = 'demo-scripted'
python .\medmarshrut_gateway_service\service.py
```

| Переменная | Что это |
|---|---|
| `REVIEWER_TOKEN` | токен врача для сервиса снимков, не короче 16 символов |
| `PATH_ADMIN_TOKEN` | токен сотрудника для сервиса пути, не короче 16 символов |
| `PATH_MIS_TOKEN` | необязательный токен МИС для итогов визита; если задан — не короче 16 символов |
| `CLINIC_SHARED_SECRET` | секрет подписи для сервиса клиники, не короче 16 символов |
| `CLINIC_STAFF_TOKENS` | JSON «токен → `clinic_id`», как у сервиса клиники; должен содержать свою клинику |
| `GATEWAY_HOME_CLINIC` | своя клиника, по умолчанию `clinic-central` |
| `GATEWAY_STATE_DIR` | папка состояния стенда, обязательна; учебные архивы шлюз берёт из `kit/` в ней |
| `GATEWAY_DATABASE_URL`, `GATEWAY_DB_SCHEMA` | серверное подключение PostgreSQL (`sslmode=require` или строже) и схема шлюза; в браузер не попадают |
| `GATEWAY_CONCLUSIONS` | заготовки заключений демо-стенда по коду находки, по умолчанию `demo_stand/conclusions.demo.json` |
| `GATEWAY_PEOPLE` | путь к `people.demo.json`, по умолчанию `demo_stand/people.demo.json` |
| `GATEWAY_IMAGING_MODE` | `demo-scripted`, `model` или `no-model` (по умолчанию) — для подписи в интерфейсе |
| `IMAGE_URL`, `PATH_URL`, `CLINIC_URL` | адреса сервисов, по умолчанию порты 8766, 8765, 8764; только хост `127.0.0.1` |
| `GATEWAY_PORT` | порт шлюза, по умолчанию 8763 |
| `ANTHROPIC_API_KEY` | необязательный ключ Claude API для ИИ-помощника; без него помощник выключен, остальное работает |
| `GATEWAY_ASSISTANT_MODEL` | модель помощника, по умолчанию `claude-sonnet-5-5` |

Если обязательной переменной нет или секрет короче 16 символов, шлюз не стартует и называет переменную.

## Роли и сессии

**Пароля нет: это локальный демо-стенд.** Роль выбирается кнопкой, `/api/health` отдаёт `"auth": "demo-roles"`. Для пилота нужна настоящая аутентификация.

Роли: `patient`, `staff`, `doctor`, `partner`. Кто за ними стоит, записано в `demo_stand/people.demo.json`: сотрудник — координатор Наталья, врач — `doctor-demo`, партнёр — сотрудник выбранной клиники-партнёра, пациент — псевдоним из сервиса клиники.

У каждой роли своя сессия и своя кука `mm_session_<роль>` (`HttpOnly; SameSite=Strict; Path=/`). Каждый запрос к `/api/` несёт заголовок `X-MM-Role` с ролью окна, и шлюз берёт куку этой роли. Поэтому окна разных ролей в одном браузере работают одновременно. Роль окна страница хранит в адресе (`#role=staff`). Сессии живут в памяти процесса 12 часов и пропадают при перезапуске.

`actor`, `physician_id`, `author_id`, `clinic_id` и `created_by` для запросов к сервисам берутся из сессии (`Session.actor`, `Session.clinic_id`), не из тела запроса. `patient_ref` пациента тоже берётся из сессии. Проверка «объект принадлежит пациенту этой сессии» — `sessions.ensure_owner`: для чужого объекта она отвечает 404, чтобы чужие идентификаторы ничего не раскрывали.

## Маршруты

| Маршрут | Роли | Что делает |
|---|---|---|
| `GET /`, `GET /assets/...` | без сессии | веб-приложение из папки `web/` |
| `GET /api/health` | без сессии | состояние шлюза и трёх сервисов |
| `POST /api/session` | без сессии | `{"role", "patient_ref"?, "clinic_id"?}` → 201 `{"role", "name", "clinic_id" \| "patient_ref"}` |
| `GET /api/session` | все четыре | сессия роли из `X-MM-Role` или 401 |
| `DELETE /api/session` | все четыре | завершает сессию роли |
| `POST /api/patient/studies?task=&consent=1` | пациент | тело `application/zip` до 50 МиБ: манифест, `POST /v1/studies`, запись в `study_registry` с `patient_ref` сессии |
| `POST /api/staff/studies?task=&patient_ref=` | сотрудник | то же от имени клиники: имитация выгрузки из РИС |
| `GET /api/demo/studies` | пациент, сотрудник | учебные архивы `upload-*` из `kit/` папки состояния |
| `POST /api/demo/studies/{name}/submit` | пациент, сотрудник | отправка учебного архива: пациент — `{"consent": true}`, сотрудник — `{"patient_ref"}` и любой архив набора |
| `GET /api/patient/studies` | пациент | свои исследования: до подтверждения только статус, после — заключение врача, объяснение, шаг плана, срез |
| `GET /api/patient/studies/{id}/images/{sop_uid}.png` | пациент | срез своего исследования, только после подтверждения |
| `GET /api/doctor/studies` | врач | реестр плюс `GET /v1/review/{id}` по каждой записи |
| `GET /api/doctor/studies/{id}` | врач | срезы, признаки с местом, ограничения модели, сведения о файлах, заготовка заключения; у исследования в `awaiting_physician` — `preview` по каждому коду находки (шаги или причина ручного разбора — код `manual_reason` и текст `manual_reason_text` — и версия правил через `POST /v1/rules/dry-run`, плюс утверждённое объяснение или `null`). `confidence` в запрос не входит; сервис пути недоступен — `preview: null` |
| `GET /api/doctor/studies/{id}/images/{sop_uid}.png` | врач | срез в PNG |
| `POST /api/doctor/studies/{id}/confirm` | врач | `{"conclusion", "finding_code"?}` → `POST /v1/review/{id}`; итог `next`: эпизод, первый шаг и его статус `step_status` или причина |
| `GET /api/doctor/visits` | врач | визиты по шагам `confirmed`/`attended`; у визита `appointment` — специалист, место и формат из `appointments` и `slots`, или `null` для записи у партнёра |
| `GET /api/staff/studies/manual` | сотрудник, врач | «Снимки на ручном описании» и подтверждения, не дошедшие до сервиса маршрута; без причины и вывода модели |
| `GET /api/staff/patients?limit=&status=` | сотрудник, врач | `GET /v1/patients` с токеном своей клиники; `limit` — целое от 1 до 500, проверяется до вызова |
| `GET /api/staff/patients/{patient_ref}/card` | сотрудник, врач | `id` по псевдониму, затем `GET /v1/patients/{id}/card` |
| `POST /api/staff/patients/{patient_ref}/anamnesis` | сотрудник, врач | `{"kind", "text", "shareable", "code"?}`; `author_id`, `author_role` и `clinic_id` из сессии |
| `GET /api/staff/episodes/{id}/route-candidates` | сотрудник, врач | подписанный `POST /v1/route-candidates`, область — из заключения эпизода; `reason_text` по-русски |
| `POST /api/staff/episodes/{id}/steps/{step}/referral` | сотрудник | `{"to_clinic_id", "reason"}` → подписанный `POST /v1/referrals` и связь в `referral_links`; повтор не создаёт второе направление |
| `POST /api/staff/episodes/{id}/steps/{step}/confirm` с `{"partner_time", "partner_clinic_id"}` | сотрудник | запись у партнёра: `offer` и `confirm` с этим временем, `evidence` «Запись у партнёра: …»; только после `accept` |
| `GET /api/staff/referrals` | сотрудник | `GET /v1/referrals` плюс имена клиник и связь с шагом |
| `POST /api/staff/referrals/{id}/cancel` | сотрудник | отмена направления своей клиники |
| `GET /api/staff/network` | сотрудник | клиники, партнёры, показатели сервиса клиники, число направленных и принятых по клиникам |
| `GET /api/partner/queue`, `GET /api/partner/referrals` | партнёр | очередь и направления с токеном клиники-партнёра |
| `GET /api/partner/patients/{id}/card` | партнёр | карта ровно в том виде, в каком её отдал сервис клиники |
| `POST /api/partner/referrals/{id}/{accept\|reject\|complete}` | партнёр | `{"note"?}`, `actor` из сессии; в сервис пути ничего не уходит |
| `GET /api/patient/documents` | пациент | свои направления: клиника, причина, статус |
| `GET /api/assistant/status` | все четыре | `{"enabled"}`: есть ли у шлюза ключ API помощника |
| `POST /api/doctor/studies/{id}/assistant/rewrite` | врач | `{"finding_code", "text"}` → `{"suggestion"}`; только для исследования, которое ждёт врача; ничего не сохраняет |
| `POST /api/patient/studies/{id}/assistant/explain` | пациент | `{}` → `{"explanation"}`; только своё и только подтверждённое исследование; ответ кешируется в `assistant_texts` |

Новый маршрут добавляется в `Gateway.routes` и в `Gateway.access` (роли). Маршрут без строки в `access` отвечает 403: по умолчанию запрещено. Шаблон пути может содержать `{параметр}`.

Порядок проверок: `Host` не из списка — 403; неизвестный путь — 404; для изменяющих запросов чужой `Origin` — 403, нет `X-MM-Role` — 401, тип не JSON — 415, тело больше 32 КиБ — 413; нет сессии этой роли — 401; роли нет в таблице доступа — 403. Маршруты загрузки архива (`Gateway.raw_routes`) вместо JSON ждут `application/zip` до 50 МиБ по `Content-Length` и читают тело только после проверки сессии и роли.

## Исследования

У сервиса снимков нет списка заданий и нет связи задания с пациентом до подтверждения, поэтому шлюз ведёт `study_registry` в своей схеме PostgreSQL (миграция `002_study_registry`): `job_id` сервиса снимков, клиника, `patient_ref`, задача, кто загрузил, время согласия. Сервис снимков держит задания в памяти: после его перезапуска запись реестра остаётся, а исследование показывается «Недоступно: сервис снимков перезапущен». Чистый `start.py` очищает реестр вместе с рабочими таблицами, `--keep` — нет.

**Манифест.** Сервис требует перечень UID. Шлюз собирает его из самого архива: читает `StudyInstanceUID`, `SeriesInstanceUID` и `SOPInstanceUID` из заголовков (`stop_before_pixels=True`, значения тегов в журнал не пишутся) и добавляет задачу из интерфейса. До чтения файлов по заголовкам ZIP проверяются лимиты сервиса: не больше 512 файлов, 40 МиБ на файл, 200 МиБ в сумме. Несколько исследований в одном архиве — отказ. Остальное проверяет сервис. **Манифест, собранный из самого архива, не защищает от неполной выгрузки:** если часть срезов не попала в архив, её нет и в перечне. В рабочей интеграции манифест приходит из РИС.

**Кто что видит.** До подтверждения врачом пациент видит только статус исследования; координатор — пациента, вид исследования и время для исследований на ручном описании. Причину ручного разбора, признаки, оценку модели и срезы получает только врач. Пациент после подтверждения получает текст врача, утверждённое объяснение (`finding_texts`), шаг плана и срез с подписью «Признак на срезе 2 из 3» или «Проекция L-CC»; оценку модели — никогда.

**Заключение.** Строки `draft` сервиса содержат оценку и UID, поэтому в поле заключения не попадают. Заготовку готовит шлюз: на демо-стенде (`model_version` с `demo-`) — текст из `GATEWAY_CONCLUSIONS` по коду находки, с настоящей моделью — название исследования, описание признака и место. `physician_id` берётся из сессии, `patient_ref` — из реестра, `edits` — `["Текст черновика изменён врачом"]`, если текст отличается от заготовки. Тело больше 8192 байт шлюз не отправляет.

**Клиника-партнёр.** Роль `partner` открывает сессию с `clinic_id` клиники-партнёра; токен к сервису клиники шлюз выбирает по клинике сессии, сотрудник своей клиники не может действовать от имени партнёра и наоборот. Партнёру шлюз отдаёт ровно то, что вернул сервис: до `accept` — псевдоним и записи анамнеза с `shareable: true`, после — ещё ФИО, дату рождения, пол и контакт. Список клиник-партнёров для окна — поле `partner_clinics` в `/api/health`. Кука у роли одна, поэтому в одном браузере открыта одна клиника-партнёр.

**Связь направления с шагом.** `referral_links` (миграция `003`): `referral_id` ↔ эпизод и шаг сервиса пути. Связь пишется, когда направление создано через шлюз. Если сервис клиники принял направление, а связь не записалась, шлюз отвечает 503; повтор находит действующее направление этой пары клиник и дописывает связь, второго направления не будет. Направления, созданные в сервисе клиники напрямую, видны без связи. Чистый `start.py` очищает таблицу, `--keep` — нет.

**ИИ-помощник (задание 11).** `assistant.py` вызывает Claude через официальный пакет `anthropic` (`client.beta.messages.create`, `effort: low`, резерв `fallbacks: "default"` под бетой `server-side-fallback-2026-07-01`, тайм-аут 30 секунд, не больше двух повторов). Помощник работает с текстом и ничего не решает: находка, код, срок и план от него не зависят. В API уходят название исследования, описание признака и место («Проекция PA»), текст врача, утверждённое объяснение и описание шага плана. Не уходят ФИО, `patient_ref`, оценка модели, `model_version`, UID и строки `draft`. Ответ с `stop_reason`, отличным от `end_turn`, пустой или длиннее лимита (поле заключения у врача, 1500 символов у пациента), а также любая ошибка SDK — 503 `assistant_unavailable`, текст не показывается. Пояснение для пациента хранится в `assistant_texts` (миграция `004`) по хешу входа, модели и версии промпта: повтор не вызывает API, новый текст врача или новый шаг дают новое пояснение. В stderr шлюза — одна строка на вызов: маршрут, исследование, модель, `stop_reason`, токены, время; текстов запроса и ответа там нет. Ключ читается только из окружения шлюза; `start.py` убирает его из окружения трёх сервисов и не выдаёт шлюзу на `--smoke` и `--web-check`.

**PNG.** Срез из `GET /v1/review/{id}/images/{sop_uid}` приводится к 0–255 по минимуму и максимуму кадра, `MONOCHROME1` инвертируется. Это просмотр для проверки, а не диагностический просмотрщик.

## Защита

- Слушает `127.0.0.1` (адрес задаёт `GATEWAY_BIND`, на Railway — `0.0.0.0`); `Host` должен быть `127.0.0.1:<порт>`, `localhost:<порт>` или домен из `GATEWAY_PUBLIC_HOSTS` (список через запятую, `https://` и `/` в конце отбрасываются).
- `POST`, `PUT`, `PATCH`, `DELETE` — только с `Origin` шлюза (для публичного домена — `https://<домен>`) или без него, с `X-MM-Role` и `Content-Type: application/json`.
- На каждом ответе `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`, на ответах API `Cache-Control: no-store`, на HTML — строгий `Content-Security-Policy` (скрипты только из файлов).
- Статика — только из `web/`, по списку расширений, без выхода за пределы папки. В списке есть `.webp` (картинки) и `.otf` (шрифт кабинета врача); CSP разрешает `font-src 'self'`.
- `GET /api/health` отдаёт `brand_font`: лежит ли на диске `web/fonts/Stolzl-Regular.otf`. Шрифт в git не входит (коммерческий), поэтому приложение запрашивает его только при `brand_font: true`.
- Трассировки уходят в stderr шлюза, в ответ — только `{"error": {"code": "internal", ...}}`.

## Ошибки

Формат: `{"error": {"code", "message", "detail"?}}`. `message` по-русски: что случилось и что делать. `detail` — английский оригинал ошибки сервиса, его видят только сотрудник, врач и партнёр.

| Код | Когда |
|---|---|
| 400 `invalid_input`, `unknown_patient`, `foreign_patient`, `inactive_patient`, `unknown_clinic` | неверный запрос |
| 400 / 409 `upstream_rejected` | сервис отклонил запрос; текст выбран по сообщению сервиса (`upstream.MESSAGES`) |
| 401 `no_session` | нет роли окна или сессии этой роли |
| 403 `forbidden`, `forbidden_host`, `forbidden_origin` | доступ запрещён |
| 404 `not_found` | нет такого адреса или объекта |
| 409 `not_confirmed` | пояснение помощника до подтверждения врачом |
| 503 `assistant_unavailable` | у шлюза нет ключа API, API не ответил или ответ не прошёл проверку |
| 502 `upstream_unavailable` | сервис недоступен или оборвал соединение |
| 502 `upstream_auth` | сервис не принял токен шлюза — стенд нужно перезапустить |
| 504 `upstream_timeout` | сервис не ответил за 10 секунд |

| `pages/*.js` | экраны пациента и сотрудника из прототипа, «Карта сервисов», форма плана прежнего каркаса |
| `path-ui.js`, `path-extra.js` | экраны пациента и координатора на сервисе пути; правила и аналитика координатора |
| `imaging-ui.js` | «Что на снимке» пациента, загрузка архива, «Снимки на ручном описании» у координатора |
| `clinic-ui.js` | карточка обращения, партнёры, документы, окно клиники-партнёра |
| `rescan-ui.js` | кабинет врача rescan: логотип, шапка, рельса, загрузчики данных, «Настройки», колокольчик |
| `rescan-today.js`, `rescan-studies.js`, `rescan-patients.js`, `rescan-visits.js`, `rescan-plan.js` | разделы кабинета «Сегодня», «Исследования», «Пациенты», «Приёмы» и общая форма плана врача |
| `actions.js` | действия и обработчики событий (делегирование по `data-*`) |
| `api.js` | обёртка над `fetch`: `X-MM-Role`, JSON, ошибки шлюза, новая сессия при 401 |
| `main.js` | запуск: адрес ↔ роль и экран, сессия роли, опрос `/api/health` |

Роль и экран окна живут в адресе: `#/patient/plan`, `#/staff/case`, `#/doctor/rsStudies`. Данные демо-разделов пока в памяти вкладки, как в прототипе; на сервисы экраны переходят в заданиях 04–07. Любое значение из данных попадает в разметку через `safe()`.

**Кабинет врача rescan (задание 12).** У врача пять экранов: `rsToday`, `rsStudies`, `rsPatients`, `rsVisits`, `rsSettings`. Прежние адреса врача (`#/doctor/reading`, `#/doctor/inbox` и другие) открывают `rsToday`. Стили — `rescan.css`, все под `#clinic` и префиксом `c-`, поэтому экраны координатора и партнёра не меняются. Картинки органов и форм препаратов — `web/img/rescan/*.webp`. Шрифт Stolzl (`web/fonts/Stolzl-Regular.otf`) коммерческий и в git не входит: его раскладывает `prototype/rescan_extract.py` из образца `prototype/rescan-app-standalone.html`, который тоже хранится только локально. Без файла кабинет показывается системным шрифтом. Списки перечитываются раз в 15 секунд; открытое исследование и открытые формы по таймеру не перерисовываются.

Проверки в браузере — `demo_stand/web_check.py`, запуск `python start.py --web-check`.

## Тесты

```powershell
python -B -m unittest discover -s ./medmarshrut_gateway_service -p "test_*.py" -v
```

Вместо настоящих сервисов тесты поднимают поддельные HTTP-серверы на свободных портах. `test_study_registry.py` работает с настоящим PostgreSQL во временных схемах и запускается, только если задан `GATEWAY_TEST_DATABASE_URL` (и `GATEWAY_TEST_SUPABASE_PROJECT_REF`, для `127.0.0.1` — `local`); без них пропускается. Манифест из учебных архивов проверяется настоящими `parse_manifest` и `inspect_archive` сервиса снимков в отдельном процессе. Подпись сверяется с `medmarshrut_path_service/auth.py`, загруженным через `importlib` под другим именем модуля. Настоящие сервисы проверяет `python start.py --smoke`. `test_assistant.py` заменяет клиент SDK заглушкой: сети в тестах нет, настоящий API не вызывается.
