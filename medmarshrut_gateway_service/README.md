# Шлюз МедМаршрута

Шлюз раздаёт веб-приложение, держит сессии с ролями и сам ходит в сервисы снимков, пути и клиники. Браузер обращается только к шлюзу: токены и секреты сервисов остаются в процессе шлюза и в ответы не попадают.

Только стандартная библиотека Python. Слушает `127.0.0.1:8763`.

## Запуск

Обычно шлюз поднимает `python start.py` вместе с тремя сервисами. Ручной запуск из корня репозитория, когда сервисы уже работают:

```powershell
python start.py --print-secrets   # в другом окне; скопируйте строки $env:...
$env:GATEWAY_STATE_DIR = "$env:TEMP\medmarshrut-stand"
$env:GATEWAY_IMAGING_MODE = 'demo-scripted'
python .\medmarshrut_gateway_service\service.py
```

| Переменная | Что это |
|---|---|
| `REVIEWER_TOKEN` | токен врача для сервиса снимков, не короче 16 символов |
| `PATH_ADMIN_TOKEN` | токен сотрудника для сервиса пути, не короче 16 символов |
| `PATH_MIS_TOKEN` | необязательный токен МИС для итогов визита; если задан — не короче 16 символов |
| `CLINIC_SHARED_SECRET` | секрет подписи для сервиса клиники, не короче 16 символов |
| `CLINIC_STAFF_TOKENS` | JSON «токен → `clinic_id`», как у сервиса клиники; должен содержать свою клинику |
| `GATEWAY_HOME_CLINIC` | своя клиника, по умолчанию `clinic-central` |
| `GATEWAY_STATE_DIR` | папка состояния стенда, обязательна; там лежит `gateway.sqlite3` |
| `GATEWAY_PEOPLE` | путь к `people.demo.json`, по умолчанию `demo_stand/people.demo.json` |
| `GATEWAY_IMAGING_MODE` | `demo-scripted`, `model` или `no-model` (по умолчанию) — для подписи в интерфейсе |
| `IMAGE_URL`, `PATH_URL`, `CLINIC_URL` | адреса сервисов, по умолчанию порты 8766, 8765, 8764; только хост `127.0.0.1` |
| `GATEWAY_PORT` | порт шлюза, по умолчанию 8763 |

Если обязательной переменной нет или секрет короче 16 символов, шлюз не стартует и называет переменную.

## Роли и сессии

**Пароля нет: это локальный демо-стенд.** Роль выбирается кнопкой, `/api/health` отдаёт `"auth": "demo-roles"`. Для пилота нужна настоящая аутентификация.

Роли: `patient`, `staff`, `doctor`, `partner`. Кто за ними стоит, записано в `demo_stand/people.demo.json`: сотрудник — координатор Наталья, врач — `doctor-demo`, партнёр — сотрудник выбранной клиники-партнёра, пациент — псевдоним из сервиса клиники.

У каждой роли своя сессия и своя кука `mm_session_<роль>` (`HttpOnly; SameSite=Strict; Path=/`). Каждый запрос к `/api/` несёт заголовок `X-MM-Role` с ролью окна, и шлюз берёт куку этой роли. Поэтому окна разных ролей в одном браузере работают одновременно. Роль окна страница хранит в адресе (`#role=staff`). Сессии живут в памяти процесса 12 часов и пропадают при перезапуске.

`actor`, `physician_id`, `author_id`, `clinic_id` и `created_by` для запросов к сервисам берутся из сессии (`Session.actor`, `Session.clinic_id`), не из тела запроса. `patient_ref` пациента тоже берётся из сессии. Проверка «объект принадлежит пациенту этой сессии» — `sessions.ensure_owner`: для чужого объекта она отвечает 404, чтобы чужие идентификаторы ничего не раскрывали.

## Маршруты

| Маршрут | Роли | Что делает |
|---|---|---|
| `GET /`, `GET /assets/...` | без сессии | веб-приложение из папки `web/` |
| `GET /api/health` | без сессии | состояние шлюза и трёх сервисов |
| `POST /api/session` | без сессии | `{"role", "patient_ref"?, "clinic_id"?}` → 201 `{"role", "name", "clinic_id" \| "patient_ref"}` |
| `GET /api/session` | все четыре | сессия роли из `X-MM-Role` или 401 |
| `DELETE /api/session` | все четыре | завершает сессию роли |

Новый маршрут добавляется в `Gateway.routes` и в `Gateway.access` (роли). Маршрут без строки в `access` отвечает 403: по умолчанию запрещено. Шаблон пути может содержать `{параметр}`.

Порядок проверок: `Host` не из списка — 403; неизвестный путь — 404; для изменяющих запросов чужой `Origin` — 403, нет `X-MM-Role` — 401, тип не JSON — 415, тело больше 32 КиБ — 413; нет сессии этой роли — 401; роли нет в таблице доступа — 403.

## Защита

- Слушает только `127.0.0.1`; `Host` должен быть `127.0.0.1:<порт>` или `localhost:<порт>`.
- `POST`, `PUT`, `PATCH`, `DELETE` — только с `Origin` шлюза или без него, с `X-MM-Role` и `Content-Type: application/json`.
- На каждом ответе `X-Content-Type-Options: nosniff` и `Referrer-Policy: no-referrer`, на ответах API `Cache-Control: no-store`, на HTML — строгий `Content-Security-Policy` (скрипты только из файлов).
- Статика — только из `web/`, по списку расширений, без выхода за пределы папки.
- Трассировки уходят в stderr шлюза, в ответ — только `{"error": {"code": "internal", ...}}`.

## Ошибки

Формат: `{"error": {"code", "message", "detail"?}}`. `message` по-русски: что случилось и что делать. `detail` — английский оригинал ошибки сервиса, его видят только сотрудник, врач и партнёр.

| Код | Когда |
|---|---|
| 400 `invalid_input`, `unknown_patient`, `foreign_patient`, `inactive_patient`, `unknown_clinic` | неверный запрос |
| 400 / 409 `upstream_rejected` | сервис отклонил запрос; текст выбран по сообщению сервиса (`upstream.MESSAGES`) |
| 401 `no_session` | нет роли окна или сессии этой роли |
| 403 `forbidden`, `forbidden_host`, `forbidden_origin` | доступ запрещён |
| 404 `not_found` | нет такого адреса или объекта |
| 502 `upstream_unavailable` | сервис недоступен или оборвал соединение |
| 502 `upstream_auth` | сервис не принял токен шлюза — стенд нужно перезапустить |
| 504 `upstream_timeout` | сервис не ответил за 10 секунд |

## Файлы

| Файл | Что это |
|---|---|
| `service.py` | конфигурация, маршруты, доступ, защита, статика |
| `sessions.py` | роли, сессии, люди стенда, `ensure_owner` |
| `upstream.py` | клиенты сервисов: токены, подпись, тайм-ауты, проверка типов, перевод ошибок |
| `errors.py` | `GatewayError` |
| `store.py` | SQLite шлюза; таблицы появятся в заданиях 04–07 |
| `web/` | временная страница: выбор роли и состояние сервисов |

## Тесты

```powershell
python -B -m unittest discover -s ./medmarshrut_gateway_service -p "test_*.py" -v
```

Вместо настоящих сервисов тесты поднимают поддельные HTTP-серверы на свободных портах. Подпись сверяется с `medmarshrut_path_service/auth.py`, загруженным через `importlib` под другим именем модуля. Настоящие сервисы проверяет `python start.py --smoke`.
