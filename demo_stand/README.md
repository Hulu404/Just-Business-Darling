# Демо-стенд МедМаршрута

Стенд поднимает три настоящих сервиса — снимков, пути и клиники — и наполняет их учебными случаями. На нём цепочка «снимок → подтверждение врача → эпизод → шаг → клиника-партнёр» проходит через настоящие API, а не через заглушки.

Всё в этой папке нужно только для демонстрации. Код сервисов стенд не меняет: свои правила и сеть клиник он подставляет через `PATH_RULES` и `CLINIC_NETWORK`.

## Запуск

Из корня репозитория:

```powershell
python -m pip install -r .\medmarshrut_image_service\requirements.txt
python start.py
```

| Команда | Что делает |
|---|---|
| `python start.py` | чистый стенд, наполнение, работа до Ctrl+C |
| `python start.py --smoke` | чистый стенд, наполнение, сквозная проверка, остановка; код завершения 0 — всё прошло |
| `python start.py --no-seed` | стенд без учебных случаев |
| `python start.py --keep` | не очищать папку состояния; наполнение не запускается |
| `python start.py --state-dir D:\stand` | другая папка состояния (по умолчанию `%TEMP%\medmarshrut-stand`) |
| `python start.py --image real` | настоящий сервис снимков вместо сценарного (с `MODEL_CONFIG`, если он задан) |
| `python start.py --print-secrets` | напечатать секреты запуска для ручной работы с API |

Секреты и токены создаются заново на каждый запуск и живут только в памяти `start.py` и его дочерних процессов. На диск и в консоль они не попадают, пока вы не попросите `--print-secrets`.

Каждый запуск начинается с пустой папки состояния. Задания сервиса снимков живут в памяти процесса: после перезапуска старые базы пути и клиники ссылались бы на задания, которых уже нет. Поэтому `--keep` сохраняет базы, но наполнение отключает.

Если порт 8764, 8765 или 8766 занят, `start.py` скажет об этом и ничего не запустит. Журналы сервисов лежат в `logs/` папки состояния.

## Что на стенде учебное

Всё. Реальных пациентов, снимков и секретов здесь нет.

- **Исследования** (`synthetic_dicom.py`) — рисунки 256×256: градиент и круги. Тегов пациента нет. КТ органов грудной клетки (3 среза), МРТ коленного сустава (3 среза), маммография (4 проекции).
- **Признаки на снимках заданы сценарием.** Обученной модели у команды нет, поэтому `image_demo_runner.py` запускает настоящий сервис снимков со сценарным backend: признак берётся из `index.json` по `StudyInstanceUID`, пиксели не анализируются. Исследование не из учебного набора получает отказ и уходит на ручной разбор. Пустой список признаков — «находок нет», такое исследование сервис тоже отправляет на ручной разбор. У результата `model_version` начинается с `demo-`, `confidence` равен `0.0`, в ограничениях стоит пометка «Демо-сценарий». По префиксу `demo-` интерфейс вешает плашку «демо-сценарий» и скрывает оценку модели.
- **Правила маршрута** (`rules.demo.json`) — пример работы маршрутизатора, **а не клинические рекомендации**. Правило для маммографии не утверждено намеренно: на нём видно, что без утверждённого правила случай уходит врачу.
- **Сеть клиник** (`network.demo.json`) — три вымышленные клиники: «Линия здоровья» (домашняя для всех пациентов), диагностический центр на Лесной и маммологический центр «Опора».
- **Люди** (`people.demo.json`) — вымышленные сотрудники, демо-роли интерфейса и семь пациентов. Контакты пациентов — адреса в домене `example.invalid`.
- **Заключения** (`conclusions.demo.json`) — тексты, которыми врач стенда подтверждает исследования. В них нет оценок модели и UID.

## Что лежит в папке состояния

| Путь | Что это |
|---|---|
| `kit/*.zip`, `kit/*.manifest.json` | учебные архивы и манифесты к ним |
| `kit/index.json` | `StudyInstanceUID` → заданные признаки, его читает сценарный backend |
| `kit/kit.json` | каталог архивов: вид исследования, название, коды признаков |
| `studies.json` | реестр наполнения: идентификатор задания сервиса снимков → `patient_ref`, название исследования |
| `path.sqlite3`, `clinic.sqlite3` | базы сервисов пути и клиники |
| `logs/` | stdout и stderr сервисов |

Архивы `upload-*` в `kit/` не использует наполнение: их можно загружать из интерфейса. Архивы `smoke-*` использует смоук-проверка.

Все пациенты зарегистрированы в клинике «Линия здоровья», у каждого две-три записи анамнеза; часть из них партнёру не видна (`shareable: false`). Наполнение идёт только через публичные API сервисов.

С `--image real` настоящий сервис снимков без модели отправляет все исследования на ручной разбор, и наполнение честно это покажет: эпизодов в сервисе пути не будет.

## Ручная работа с API

```powershell
python start.py --print-secrets
```

Скопируйте строки `$env:...` во второе окно PowerShell. После этого можно вызывать API сервисов напрямую или запускать скрипты стенда, например `python .\demo_stand\smoke.py` (ему нужна ещё `$env:DEMO_STATE_DIR` — путь к папке состояния).
